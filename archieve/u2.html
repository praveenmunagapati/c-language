01 · top-down design

BUILDING FROM EXISTING INFO

  • Reuse before rewrite — if a solved problem is close to your new one, adapt its algorithm and code rather than starting from scratch.
  • Modify an existing program — change variable names, adjust computations, add I/O — preserving the tested structure.
  • Combine pieces — the standard library and your own past functions are building blocks. Connect them with new logic.
  • Case study approach — study a working solution, trace its data flow, then extend it. Never copy blindly — understand every line.
reuse-example.c
/* Original: convert miles → km */
double kms = miles * 1.609;

/* Adapted: convert kg → lbs
   SAME pattern — different constant */
double lbs = kg * 2.205;

/* Build from library pieces */
#include <math.h>
hypotenuse = sqrt(pow(a, 2) + pow(b, 2));
/* sqrt() and pow() already exist —
   no need to reinvent them */
02 · top-down design

LIBRARY FUNCTIONS

Header Function Purpose
math.h sqrt(x) square root of x
math.h pow(x,y) x raised to power y
math.h fabs(x) absolute value (double)
math.h ceil(x) / floor(x) round up / down
stdlib.h abs(n) absolute value (int)

HOW TO USE
#include the header → call the function → link with -lm (math library on Unix). The compiler sees the prototype from the header and checks your call.
math_demo.c
#include <stdio.h>
#include <math.h>

int main(void)
{
    double x = 16.0, y = 2.0;

    printf("sqrt(%.0f) = %.1f\n",
           x, sqrt(x));       → 4.0

    printf("pow(%.0f,%.0f) = %.0f\n",
           x, y, pow(x, y));  → 256

    printf("ceil(2.3)  = %.0f\n",
           ceil(2.3));       → 3

    printf("floor(2.9) = %.0f\n",
           floor(2.9));      → 2

    return (0);
}

04 · functions

FUNCTIONS WITHOUT ARGUMENTS

no_args.c
#include <stdio.h>

/* function PROTOTYPE — declaration */
void print_banner(void);

int main(void)
{
    print_banner();  ← call
    printf("Processing...\n");
    print_banner();  ← reuse!
    return (0);
}

/* function DEFINITION — body */
void
print_banner(void)
{
    printf("========================\n");
    printf("  PAYROLL SYSTEM v1.0\n");
    printf("========================\n");
}
void RETURN
void means the function returns nothing — it performs an action (printing, clearing, etc.) and control returns to the caller.
void PARAMETER
(void) in the parameter list means the function takes no input — it works entirely from internal or global data.
PROTOTYPE
Placed before main(), it tells the compiler the function's signature. The definition (body) can appear later — even in another file.
⚠ ORDER MATTERS
Without a prototype, calling a function before its definition causes a compiler error (or worse, an implicit declaration bug in old C).
05 · functions

FUNCTIONS WITH INPUT ARGUMENTS

input_args.c
/* prototype: takes two doubles, returns double */
double compute_tax(double salary, double rate);

int main(void)
{
    double sal = 50000.0, r = 0.25;
    double tax;

    tax = compute_tax(sal, r);
    /*      ↑ actual arguments   */

    printf("Tax = $%.2f\n", tax);
    return (0);
}

double
compute_tax(double salary, double rate)
/*          ↑ formal parameters         */
{
    return (salary * rate);
}
Actual argument
The value passed at the call site: sal, r. Can be a variable, constant, or expression.
Formal parameter
The local variable that receives the copy: salary, rate. Exists only inside the function.
Pass by value
C copies the argument's value into the parameter. Changing salary inside does not change sal outside.
Return value
return (expr); sends one value back to the caller. The function's return type must match.
⚠ TYPE MISMATCH
If you pass an int where a double is expected, C silently promotes — but passing a double for an int parameter truncates. Watch the warnings.
06 · functions

FUNCTION PROTOTYPES

prototype.c
/* PROTOTYPE tells the compiler:
   1. function name
   2. return type
   3. number and type of parameters */

double circle_area(double);
/*                        ↑ param name optional */
void   show_result(double area);
/*                        ↑ but encouraged    */

/* Placed BEFORE main — or in a header file */

int main(void)
{
    double a = circle_area(5.0);
    show_result(a);
    return (0);
}

/* definitions can appear AFTER main */
double circle_area(double r)
{   return (3.14159 * r * r);   }

void show_result(double area)
{   printf("Area = %.2f\n", area);  }
WHY PROTOTYPES?
The compiler needs to know the function's interface before the call. Without it, it can't check argument count or types.
HEADER FILES
stdio.h is full of prototypes: printf, scanf, fopen. Your own .h files do the same for your functions.
PROTOTYPE ≠ DEFINITION
The prototype declares the signature; the definition provides the body. Both must agree on return type and parameter types exactly.
07 · functions

ANATOMY OF A FUNCTION CALL

main()
tax = compute_tax(sal, r);
──▶
COPY values
sal → salary, r → rate
──▶
EXECUTE body
salary * rate
──▶
RETURN result
12500.0
──▶
RESUME main
tax = 12500.0
call-stack trace
/* Step by step */
main:  sal = 50000, r = 0.25
       call compute_tax(50000, 0.25)
         ├── salary = 50000    ← copy of sal
         ├── rate   = 0.25     ← copy of r
         └── return 12500.0   ← sent back
main:  tax = 12500.0        ← received
STACK FRAME
Each function call creates a stack frame — local variables and parameters live there. When the function returns, the frame is destroyed.
⚠ ONE RETURN VALUE
A C function can return at most one value. Need to return multiple results? Use output parameters (pointers) — coming soon.
01 · pointers & modular

POINTERS — & AND *

pointers.c — memory model
int x = 42;
int *p;       ← p is a pointer-to-int

p = &x;      ← p now holds ADDRESS of x

/* memory picture:
   name    addr     value
   ─────   ──────   ─────
    x      0x1000    42
    p      0x1008    0x1000  ← stores x's addr
*/

printf("%d\n",  x);    → 42
printf("%p\n",  p);    → 0x1000
printf("%d\n", *p);    → 42 (dereference)

*p = 99;               ← changes x to 99!
printf("%d\n",  x);    → 99
&x
Address-of operator — returns the memory address where x is stored. You've used it with scanf all along.
int *p
Declares p as a pointer to int — a variable that stores an address of an int.
*p
Indirection (dereference) — follows the address to access the value stored there. Read or write through the pointer.
⚠ UNINITIALIZED POINTER
Using *p before assigning p = &something accesses random memory — a crash or corruption. Always initialize pointers.
02 · pointers & modular

THE INDIRECTION OPERATOR

indirection.c
int    a = 10,  b = 20;
int   *pa = &a, *pb = &b;

/* read through pointer */
int sum = *pa + *pb;     → 30

/* write through pointer */
*pa = *pa + 5;           → a is now 15

/* redirect the pointer */
pa = &b;                 → pa now points to b
printf("%d\n", *pa);     → 20 (b's value)

/* pointer to double */
double  price = 9.99;
double *pp    = &price;
*pp = *pp * 1.10;        → 10% markup
TWO MEANINGS OF *
In a declaration, int *p means "p is a pointer." In an expression, *p means "follow the pointer to the value."
POINTER ARITHMETIC
*pa + *pb adds the values pointed to, not the addresses. *pa = *pa + 5 modifies the original variable through the pointer.
REDIRECTION
Changing pa = &b does NOT change a. It just makes pa point somewhere else — a different target.
⚠ * vs &
& goes from variable → address. * goes from address → variable. They are inverses: *(&x) == x.
03 · pointers & modular

FUNCTIONS WITH OUTPUT PARAMETERS

output_params.c
/* Need to return TWO values?
   Use pointer parameters.    */

void separate(double value,
             int *whole_p,
             double *frac_p)
{
    *whole_p = (int) value;
    *frac_p  = value - *whole_p;
}

int main(void)
{
    int    w;
    double f;

    separate(7.85, &w, &f);
    /*       ↑     ↑    ↑
       input   output output   */

    printf("%d and %.2f\n", w, f);
    /* → 7 and 0.85 */
    return (0);
}
THE PATTERN
Pass the address of the variable you want filled. Inside the function, use *param_p = value; to write through the pointer.
NAMING CONVENTION
Suffix pointer parameters with _p or _ptr: result_p, count_p. Instantly signals "this is an output."
WHY NOT return?
return gives back one value. With pointers, a function can modify many variables in the caller's scope.
⚠ FORGOT THE & ?
separate(7.85, w, f) passes the values of w and f — the function can't write back. Always pass &w, &f.
04 · pointers & modular

MULTIPLE CALLS WITH I/O PARAMS

multi_call.c
/* A function with BOTH input and output params */
void scale_and_shift(
    double  val,        ← input (copy)
    double  factor,     ← input (copy)
    double *result_p)   ← output (pointer)
{
    *result_p = val * factor + 1.0;
}

int main(void)
{
    double a, b, c;

    /* call 1 */
    scale_and_shift(3.0, 2.0, &a); → a = 7.0

    /* call 2: use output as next input */
    scale_and_shift(a,   0.5, &b); → b = 4.5

    /* call 3: same function, different data */
    scale_and_shift(b,   3.0, &c); → c = 14.5

    printf("%.1f  %.1f  %.1f\n", a, b, c);
    return (0);
}
CHAINING CALLS
The output of one call becomes the input of the next. The function is reused with different data each time — true modularity.
INPUT vs OUTPUT
Input params: passed by value (copy). Output params: passed by pointer (address). The * in the declaration is the giveaway.
⚠ SAME VARIABLE AS I/O
scale_and_shift(a, 2.0, &a) is legal — a is read (copied) as input, then overwritten as output. The copy happens first.
05 · pointers & modular

SCOPE OF NAMES

scope.c
#include <stdio.h>

int global_count = 0;  ← file scope (global)

void increment(void)
{
    int local = 10;     ← function scope
    global_count++;
    printf("local=%d, global=%d\n",
           local, global_count);
}

int main(void)
{
    int x = 5;          ← main's local

    increment();         → local=10, global=1
    increment();         → local=10, global=2

    /* printf("%d", local);  ← ERROR!
       local is NOT visible here */

    printf("x=%d\n", x); → x=5 unchanged
    return (0);
}
Local scope
Variables declared inside a function. Born at entry, destroyed at return. Invisible outside.
Block scope
Variables declared inside { } — even inside a loop or if. Destroyed when the block ends.
File (global) scope
Declared outside all functions. Visible everywhere below the declaration. Lasts the entire program.
Parameter scope
Formal parameters act as local variables inside their function.
⚠ AVOID GLOBALS
Global variables make debugging hard — any function can change them. Prefer local variables + parameters. Globals are a last resort.
06 · pointers & modular

OUTPUT PARAMS AS ACTUAL ARGS

pass_through.c
/* Function A gets data via pointer */
void get_data(double *val_p)
{
    printf("Enter value> ");
    scanf("%lf", val_p);
    /*           ↑ val_p is ALREADY an address
       no & needed — val_p IS the address */
}

/* Function B passes the pointer through */
void process(double *result_p)
{
    double temp;
    get_data(&temp);
    *result_p = temp * 2.0;
    /* or directly: get_data(result_p); */
}

int main(void)
{
    double answer;
    process(&answer);
    printf("Doubled: %.2f\n", answer);
    return (0);
}
PASS-THROUGH
A pointer parameter is itself an address. You can pass it directly to another function that expects a pointer — no extra & needed.
scanf & POINTERS
scanf("%lf", val_p) — since val_p already holds an address, writing &val_p would be wrong (address of the pointer itself).
DELEGATION
Function B delegates to Function A, passing the same pointer. The final result flows all the way back to main — through a chain of pointer forwarding.
⚠ & of a POINTER
&val_p gives the address of the pointer variable, not the address it stores. This is a pointer-to-a-pointer — rarely what you want here.
07 · pointers & modular

COMPLETE MODULAR EXAMPLE

payroll_modular.c
#include <stdio.h>

/* prototypes */
void   get_input(double *hours_p, double *rate_p);
double compute_pay(double hours, double rate);
void   display(double pay);

int main(void)
{
    double hours, rate, pay;
    get_input(&hours, &rate);
    pay = compute_pay(hours, rate);
    display(pay);
    return (0);
}

void get_input(double *h, double *r) {
    printf("Hours> "); scanf("%lf", h);
    printf("Rate>  "); scanf("%lf", r);
}

double compute_pay(double h, double r) {
    if (h > 40.0)
        return 40*r + (h-40)*r*1.5;
    return h * r;
}

void display(double pay) {
    printf("Pay = $%.2f\n", pay);
}

STRUCTURE CHART

main()
orchestrate
↓ &h,&r
get_input()
output: h,r
↓ h,r
compute_pay()
returns pay
↓ pay
display()
prints result
MODULARITY WINS
Each function has ONE job. main() is just 4 lines. To change overtime rules, edit only compute_pay(). To switch to GUI output, replace only display().
08 · pointers & modular

PASS BY VALUE vs POINTER

Pass by Value Pass by Pointer
What's passed a copy of the data the address of the data
Syntax (call) func(x) func(&x)
Syntax (param) int x int *x_p
Can modify original? No Yes — via *x_p
Use for input data output / modifying data
Safety original is protected original can be changed
swap.c — classic example
/* WRONG — copies only */
void bad_swap(int a, int b) {
    int temp = a;
    a = b;           ← changes local copy
    b = temp;        ← original untouched
}

/* RIGHT — uses pointers */
void swap(int *a_p, int *b_p) {
    int temp = *a_p;
    *a_p = *b_p;     ← modifies original
    *b_p = temp;     ← modifies original
}

/* usage */
int x = 3, y = 7;
swap(&x, &y);
/* now x == 7, y == 3 ✓ */
09 · best practices

FUNCTION DESIGN GUIDELINES

01
ONE TASK
Each function should do exactly one thing. If you can't describe it in one sentence, split it.
02
NAME IT WELL
Use verb_noun: compute_tax, get_input, print_report. The name IS the documentation.
03
LIMIT PARAMS
Keep parameter lists short (≤ 4–5). Too many? Group related data into a struct.
04
NO SIDE EFFECTS
A function that returns a value should not also print or modify globals. Keep I/O separate from computation.
05
PROTOTYPE FIRST
Write the prototype before the body — it forces you to think about the interface before the implementation.
06
TEST EACH ONE
Write a small main() that calls the function with known inputs. Verify outputs before integrating.
checklist.txt
/* ask before writing a function */

✓ What does it DO?  (one sentence)
✓ What goes IN?     (input params)
✓ What comes OUT?   (return / output)
✓ Can I test it alone?
✓ Can I reuse it?
RULE OF THUMB
If a function is longer than one screen (~30 lines), it's probably doing too much. If you need a comment to explain what a section does, that section is a function waiting to be born.
