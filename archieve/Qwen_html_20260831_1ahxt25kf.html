What Is a Computer?

An electronic machine that accepts data (input), processes it by executing a stored sequence of instructions (program), and produces information (output) — at incredible speed, with zero judgment. It does exactly what it is told. Nothing more. Nothing less.

INPUT

Raw facts & figures: keystrokes, mouse clicks, file contents, sensor readings. The data the program will transform.

PROCESS

The CPU executes instructions one after another — arithmetic, comparisons, decisions. This is where your program lives and runs.

OUTPUT

The processed result: numbers on screen, printed reports, saved files. Information — data with meaning.

input ──▶ [ PROCESSING UNIT (CPU + memory) ] ──▶ output ▲ │ stored program: instructions sit in memory │ and are fetched & executed one by one
GIGO — Garbage In, Garbage Out. The machine never questions your data. Validating input is your job (you'll write that code with loops — slide 84).

Humans think in words; the CPU thinks in voltages. Programming languages are a ladder of abstraction between the two.

WHY C IS "HIGH-LEVEL"

You write pay = hours * rate; — one readable line. The machine needs many load/multiply/store steps to do it. The compiler performs that expansion for you.

WHY C IS ALSO "LOW-LEVEL"

C exposes memory addresses, pointer arithmetic and byte-sized types. That is why it powers operating systems, compilers and embedded firmware.

Translation — Source → Machine Code

C source (.c) ──compiler──▶ assembly (.s) ──assembler──▶ machine code (.o) │ linker + libraries ──────▶ executable

COMPILER

Translates the whole program at once, from high-level C to assembly/object code. Reports syntax errors before anything runs. C is a compiled language.

ASSEMBLER

Converts each assembly instruction into its exact binary opcode — a 1-to-1 mechanical translation.

THE STORED-PROGRAM CONCEPT (VON NEUMANN)

Instructions live in memory side by side with data. The CPU fetches, decodes and executes them one after another. Your .c file becomes numbers in RAM — indistinguishable in kind from the numbers they compute on.

KEY INSIGHT — "running a program" = the CPU walking through memory, instruction by instruction. Everything else in this course is about writing those instructions correctly.

Algorithms — The Recipe

An algorithm is a finite, ordered, unambiguous sequence of steps that transforms input into output and solves the problem. A recipe for a machine that has zero intuition but perfect obedience.

PropertyMeaning
Inputzero or more quantities supplied before it begins
Outputat least one result produced — otherwise it solves nothing
Definitenessevery step precisely stated — no ambiguity, ever
Finitenessmust terminate after a finite number of steps
Effectivenesseach step basic enough to be carried out exactly
"SORT THE NUMBERS NICELY" ✗ — not an algorithm: vague verb, undefined order. "Compare each pair, swap if out of order, repeat until no swap occurred" ✓ — definite, effective, finite.

Algorithm — Largest of Three

ALGORITHM LargestOfThree Step 1: read a, b, c Step 2: max ← a Step 3: if b > max then max ← b Step 4: if c > max then max ← c Step 5: print max Step 6: stop /* plain, numbered, language-free. Any C programmer can translate this directly. */

THE IDEA — "KING OF THE HILL"

Assume the first value is the champion (max ← a). Let each remaining value challenge it. The survivor is the answer. Works for 3 values or 3 million.

PATTERN TO KEEP — "assume first, challenge with the rest" is the universal maximum/minimum algorithm. You'll reuse it inside loops (slide 72+).

Structured Programming — The Discipline

PrincipleWhat it demands
Top-down designstart with the whole problem, decompose into sub-problems, refine each until directly codeable. Big problem → small modules.
Single entry, single exitevery block has exactly one way in and one way out. Control flow stays readable and traceable.
Three constructs sufficeBöhm & Jacopini proved any algorithm can be expressed with sequence, selection, repetition alone.

SPAGHETTI ✗

Variables — Named Boxes in Memory

A variable is a named memory location whose value can change while the program runs. Declaring one asks the compiler to reserve cells of the right size and remember the name.

int count = 5; name: count ← identifier (slide 35) type: int ← what kind of value fits value: 5 ← current contents addr: 1024 … ← where in RAM (compiler's problem, for now)

THREE ATOMIC TRUTHS

  • a variable holds only values of its declared type
  • assignment replaces the old value — the box keeps its name, loses its past

Assignment — Get, Then Store

kms = miles * 1.609; /* 1. evaluate the RIGHT side completely (miles * 1.609 → a value) 2. STORE that value into the LEFT side (the variable kms) 3. the old value of kms is destroyed */

RIGHT → LEFT, ALWAYS

The right side may be any expression (a whole computation). The left side must be a single variable — a destination, never a formula.

x = x + 1; /* legal! read x, add 1, store back */ x + 1 = y; /* ✗ nonsense — no destination */
ASSIGNMENT ≠ EQUALS — in C, = means "copy, right to left" — it is an action, not a mathematical claim. x = x + 1 is algebra heresy but perfect C: it increments x. Mathematical equality is == (slide 60).

The Integer Division Trap

When both operands are int, / silently throws away the fractional part. No rounding — truncation toward zero.

5 / 2 → 2 /* 0.5 lost */ 1 / 2 → 0 /* !!! */ 7 / 3 → 2 -7 / 2 → -3 /* toward 0? C99: -3 */ 5 / 2.0 → 2.5 /* one real operand → real result */ (double)5/2 → 2.5 /* cast first operand */
THE CLASSIC WRONG AVERAGE —

THE FIX — make at least one operand real: (a+b+c) / 3.0, or cast: (double)(a+b+c) / 3. Cast before dividing, not after.

Type Conversion & the Cast

IMPLICIT — THE COMPILER PROMOTES

5 * 2.5 /* int→double, result double: 12.5 */ char c = 'A'; c + 1 /* char promoted to int: 66 */ int i = 3.99; /* double→int TRUNCATES: i == 3 */

Rank ladder: char → int → float → double. In mixed expressions, the smaller type climbs to the bigger one before the operation.

EXPLICIT — THE CAST

(double) total / count /* force real division */ (int) 3.99 /* → 3, truncation */ (int)(x + 0.5) /* round to nearest int */

Form: (type) expression. The cast converts a copy — the original variable is untouched.

The Format Mismatch Bug

A placeholder must match its value's type. If it doesn't — no compiler error. Just wrong, garbage output at runtime. printf blindly reinterprets the bits.

double salary = 45000.50; printf("%d\n", salary); /* ✗ %d wants int bits; reads the double's bits as an int → prints garbage like 0 */ int age = 20; printf("%f\n", age); /* ✗ same disease, other side */ printf("%f\n", salary); /* ✓ type matches specifier */
SILENT & FREE — mismatches compile without complaint. The bug ships. Check every % against its value: %d↔int, %f↔double, %c↔char.
DEFENSE — read each printf line as a table: specifier 1 ↔ value 1, specifier 2 ↔ value 2. Counts and types must both match.

== vs = — The Classic Bug

THE BUG —
if (x = 5) { ... } /* meant ==, wrote = */

  • == has values on both sides — a question
  • inside if (...) you almost always want a question

Compound Statements — Braces Make One Block
