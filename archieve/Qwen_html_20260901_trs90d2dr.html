Nested if — and the Dangling-else Rule

NESTING — DECISIONS INSIDE DECISIONS

if (x > 0) { if (x % 2 == 0) printf("positive even\n"); else printf("positive odd\n"); }

Each level halves the possibility space — decide sign first, then parity. A whole if/else can live inside either branch of another; depth is unlimited, readability is not. Keep nesting shallow (≤ 3).

THE DANGLING else

if (a > 0) if (b > 0) printf("both\n"); else /* which if does this else belong to? */ printf("???\n");

THE RULE — an else binds to the nearest unmatched if: here the inner one, regardless of your indentation.

/* make intent explicit with braces */ if (a > 0) { if (b > 0) printf("both\n"); } else { printf("a <= 0\n"); }

The Conditional Operator ?: — Selection as an Expression

condition ? value_if_true : value_if_false max = (a > b) ? a : b; abs = (x >= 0) ? x : -x; printf("%s\n", (pass) ? "PASS" : "FAIL");

HOW TO READ IT

"If the condition holds, take the first value; otherwise take the second." The whole thing is one expression that yields a value — it can live inside assignments, arguments, even other expressions.

THE if-else TWIN

/* these are the same decision */ max = (a > b) ? a : b; if (a > b) max = a; else max = b;
USE SPARINGLY — perfect for choosing one of two values; terrible when nested or side-effecty. If your ternary spans three lines, write if-else instead.

Decision Steps in Algorithms — Pseudocode First

/* overtime pay — designed BEFORE code */ IF hours > 40.0 THEN pay = 40.0 * rate + (hours - 40.0) * rate * 1.5 ELSE pay = hours * rate ENDIF

if (hours > 40.0) pay = 40.0 * rate + (hours - 40.0) * rate * 1.5; else pay = hours * rate;

  • flowcharts express the same idea with a decision diamond (slide 23)
  • refinement order: solve the simple case first, then wrap special cases — boundaries, invalid input — in decisions around it
DESIGN HABIT — say the IF/THEN/ELSE in plain words before touching C. If you cannot state a branch condition out loud, you don't understand the problem yet (objective 05).

The Guard Pattern — Validate Before You Compute

/* GUARD: reject bad data at the door */ if (num_employees <= 0) { printf("Invalid data\n"); } else { avg = total / num_employees; printf("Average = %.2f\n", avg); } /* same shape — divide-by-zero guard */ if (denom == 0) { printf("Cannot divide\n"); } else { result = num / denom; }

WHY GUARDS

  • division by zero, negative counts, missing data — stopped before they corrupt computation
  • the real work happens only in the safe else branch
  • the pattern scales: later you wrap a loop around it — "keep asking until legal" (slide 84)
input arrives ↓ ◇ valid ? no ↓ ↘ yes reject compute safely message ↓ output ✓
GIGO DEFENSE — the machine never questions input (slide 04). Every program that touches user data needs guards; selection structures exist largely for this.

03 · repetition & loops

Why Repetition? — Machines Don't Get Bored

Print the numbers 1 to 1000. Sum a million readings. Re-prompt until the user types a legal value. Sequence and selection cannot express "again" — that is the third construct's job.

WITHOUT LOOPS ✗

printf("%d\n", 1); printf("%d\n", 2); printf("%d\n", 3); /* ...997 more lines... */ printf("%d\n", 1000);

Endless copy-paste. Change the range? Rewrite everything. A thousand lines saying one thing.

WITH LOOPS ✓

int i = 1; while (i <= 1000) { printf("%d\n", i); i = i + 1; }

Five lines. Works for any limit. Says once what must be done many times.

THE LOOP BARGAIN — you write the body once; the machine runs it as many times as the condition demands. Repetition + a changing condition = controlled repetition.

The while Statement — Pre-Test Repetition

while (condition) /* test BEFORE body */ statement; while (condition) { statement₁; /* the loop body */ statement₂; }
initialize loop-control var ↓ ◇ condition ? true ↓ ↘ false → exit body: work + update control var ↺ back to test

SEMANTICS, ATOMICALLY

  • evaluate the condition before every pass
  • true → run body → test again · false → exit
  • false from the start? the body runs zero times — legal and common
  • something in the body must move the condition toward false
PRE-TEST — while checks the door before letting you in. Zero executions is a valid outcome (e.g. input already exhausted).

Counting with while — and the Infinite Loop

/* prints 1 .. count */ int count = 5; int i = 1; /* INIT */ while (i <= count) { /* TEST */ printf("i = %d\n", i); i = i + 1; /* UPDATE */ } /* output: 1 2 3 4 5 — loop exits at i == 6 */
⚠ INFINITE LOOPS — forget the update and the condition never becomes false:
while (i <= count) printf("i = %d\n", i); /* i never changes → runs forever */
Every loop needs init + test + update. If a program "hangs", hunt for the missing update.

THE TRIPLE, MEMORIZED

INIT — where does counting start? TEST — when do we keep going? UPDATE — what moves us toward the end?

Computing a Sum — The Accumulator

/* sum of 1..10 */ double sum = 0.0; /* identity for + */ int i; for (i = 1; i <= 10; i = i + 1) sum = sum + i; /* running total */ /* sum == 55 */

PATTERN · ACCUMULATOR

  • initialize the accumulator outside the loop
  • update it inside with the running operation
  • after the loop it holds the grand total
SUM → 0 — zero is the identity for addition: adding 0 changes nothing. Any other starting value biases the total forever.
sum = 0 → 1 → 3 → 6 → 10 → 15 → … → 55 ▲ each pass adds the current i
AVERAGE FROM A SUM — count items as you go (count = count + 1), then avg = sum / count after the loop. Guard first: divide only if count > 0 (slide 68).

Computing a Product — Factorial

/* PRODUCT: accumulate factors */ double fact = 1.0; /* 1, NOT 0! */ int i; for (i = 1; i <= 5; i = i + 1) fact = fact * i; /* 5! = 120 */

SAME SHAPE, DIFFERENT IDENTITY

GoalInit toWhy
SUM0identity of addition — adding 0 changes nothing
PRODUCT1identity of multiplication — starting at 0 makes every product 0
fact = 1 → 1 → 2 → 6 → 24 → 120 i=1 i=2 i=3 i=4 i=5
fact = 0.0 ✗ — every pass then multiplies by zero: the answer stays 0 no matter what the loop does. The identity element is the whole trick.

The for Statement — The Three-in-One Header

for (i = 1; i <= n; i = i + 1) └─init──┘└─repeat-cond─┘└──update──┘ printf("%d\n", i); /* steps: init → test → body → update → test … */ /* update runs AFTER the body, every pass */

ANATOMY OF THE HEADER

SlotWhen it runsDuty

BEST FOR COUNTING — when the number of repetitions is known in advance. Init, test and update live on one line — nothing gets forgotten (compare while, where the update can wander off and cause slide 71's disaster).

for ≡ while — Same Engine, Different Bodywork

for (i = 1; i <= n; i = i + 1) printf("%d\n", i);
/* EXACTLY equivalent expansion: */ i = 1; /* init */ while (i <= n) { /* test */ printf("%d\n", i); /* body */ i = i + 1; /* update */ }
for: [init] → ◇test? → body → [update] → ◇test? → … while: init → ◇test? → body + update → ◇test? → … same four events, same order

WHEN TO PICK WHICH

Known number of passes → for (all three controls in one header). Unknown — sentinel, flag, EOF, user-driven → while. Semantics are identical; it's a readability choice.

TWO LAWS

  • never modify the control variable inside the body — let the update expression do it
  • any header slot may be empty (for (;;) = forever), but don't be clever

for Variations — and the Off-by-One Trap

/* count DOWN */ for (i = n; i >= 1; i = i - 1) printf("%d\n", i); /* step by 2 — evens */ for (i = 2; i <= 20; i = i + 2) printf("%d\n", i); /* declare in the header (C99) */ for (int k = 0; k < 5; k++) printf("%d\n", k); /* k dies here */
⚠ OFF-BY-ONE —
for (i = 1; i <= n; ...) /* runs n times */ for (i = 1; i < n; ...) /* runs n−1 times */ for (i = 0; i < n; ...) /* runs n times */
Decide which you mean. Verify by tracing with a tiny n (n = 3) — fingers are a debugger.

VARIATION RULES

  • the update may add, subtract, multiply — anything that approaches the exit
  • i++ / i-- are the idiomatic updates (slide 52)
  • a variable declared in the header exists only inside the loop

Sentinel Loops — Repeat Until the Magic Value

/* loop until a sentinel value arrives */ printf("Enter scores (-1 to stop)> "); scanf("%d", &score); /* PRIMING READ */ while (score != SENTINEL) { /* SENTINEL = -1 */ sum = sum + score; count = count + 1; scanf("%d", &score); /* get next */ } avg = sum / count;

THE SHAPE

priming read (before the loop) ↓ ◇ score != sentinel ? true ↓ ↘ false → exit body: use the value + read NEXT value ↺ back to test
⚠ PRIMING READ — the first scanf happens before the loop; each pass reads the next value at the end. Both reads are required — miss one and the loop never advances, or tests garbage.
SENTINEL-CONTROLLED — repeat until a special "end of data" value arrives (−1, 0, 999…). The count of repetitions is unknown up front — exactly when while beats for.

Flag, EOF & Validation Loops

FLAG-CONTROLLED

int found = 0; while (!found) { ... if (x == target) found = 1; }

A 0/1 variable flips when the event occurs; !found reads as "not found yet".

ENDFILE-CONTROLLED

while (scanf("%d", &x) != EOF) { sum += x; }

scanf returns EOF when input ends — drains whole files with no sentinel.

INPUT VALIDATION

while (x < 0) { printf("Non-negative> "); scanf("%d", &x); }

Keep asking until the answer is legal. Full upgrade with do-while at slide 84.

CHOOSING — known count → for · terminated data → sentinel · waiting for an event → flag · draining a stream → EOF · stubborn user → validation. Same three-question design (slide 79) governs all.

Loop Design — Answer Three Questions

Answer three questions, and any loop is correct. Miss one, and you get garbage, skipped work, or an infinite spin.

#QuestionFailure when ignored
1 · InitializeHow are the control variable and accumulators set before the first test?garbage start values, biased totals

The do-while Statement — Test at the Bottom

do { statement(s); } while (condition); /* ← semicolon! */
body: statements ↓ ◇ condition ? true ↺ repeat · false → exit

SEMANTICS, ATOMICALLY

do-while in Its Element — Input Validation

/* validate.c — test at the BOTTOM */ do { printf("Enter rate (0-10)> "); scanf("%lf", &rate); } while (rate < 0.0 || rate > 10.0); /* only a LEGAL rate reaches here */

WHY do-while FITS

  • you must ask once before you can test the answer — post-test matches reality
  • the condition states what's wrong: keep looping while illegal
  • the same shape drives menus: show → choose → repeat while not "exit"
do-while: body → ◇cond? ↺ (≥ 1 pass) while: ◇cond? → body ↺ (≥ 0 passes)
vs while — while is pre-test (may run zero times); do-while is post-test (runs at least once). Ask: "must the body happen at least once?"

break & continue — Emergency Exits

break — LEAVE NOW

for (i = 1; i <= 100; i++) { if (i == 5) break; /* exit loop entirely */ printf("%d ", i); } /* prints: 1 2 3 4 */

Jumps to the statement after the loop. In nested loops it exits only the innermost one.

continue — SKIP THIS PASS

for (i = 1; i <= 5; i++) { if (i == 3) continue; /* skip → next update */ printf("%d ", i); } /* prints: 1 2 4 5 */

Abandons the rest of this pass and jumps to the next test/update. The loop itself keeps going.

USE SPARINGLY — structured loops have one clean entry and one clean exit. Sprinkling break/continue everywhere recreates slide 26's spaghetti. Prefer fixing the condition; reserve these for genuine early-outs (target found, invalid data hit).
