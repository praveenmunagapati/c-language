WHAT IS A COMPUTER?

DEFINITION
A computer is a programmable, electronic device that accepts data (input), processes it according to stored instructions (processing), produces information (output), and can store both data and instructions (storage).
INPUT
keyboard · mouse
→
PROCESSING
CPU + memory
→

VON NEUMANN IDEA
The stored-program concept: instructions live in memory like data. The machine can be re-tasked by loading new instructions — that's what makes it a computer, not a calculator.

atom 06 · hardware

INSIDE THE CPU

ALU
Arithmetic Logic Unit — performs +, −, ×, ÷ and comparisons (>, ==…). Every C arithmetic expression ends up here.
CONTROL UNIT
CU — fetches instructions from memory, decodes them, and commands the other units. The orchestra conductor.
REGISTERS
Tiny, ultra-fast cells inside the CPU holding values being worked on right now — the machine's scratchpad.
CLOCK
Synchronizes everything; its speed (GHz = billions of ticks/second) bounds how fast instructions complete.
FETCH–DECODE–EXECUTE
The eternal cycle: fetch next instruction from memory → decode what it means → execute it → repeat. Billions of times per second.
machine-cycle.c — as the CPU sees it
while (power_on) {
    instruction = fetch(PC);   // program counter
    meaning     = decode(instruction);
    execute(meaning);         // ALU or memory
    PC = PC + 1;               // next instruction
}
/* a running C program is this loop,
   unrolled into billions of cycles */
WHY YOU CARE
Every statement you write in C is ultimately a short sequence of these machine cycles. Simpler expressions = fewer cycles = faster programs.

SOFTWARE TAXONOMY

software tree
software/
├── system/            — runs the machine
│    ├── OS (UNIX, Linux, Windows)
│    ├── compiler (cc, gcc)
│    ├── linker · loader · editor
└── application/       — solves user problems
     ├── payroll · games · browsers

   application software uses system software */
KEY INSIGHT
The compiler itself is a program: input = your .c file, output = machine code. Programs that build programs — that's the software food chain.
OPERATING SYSTEM
Allocates CPU, memory, and devices among programs. Your return (0) hands control back to it — that's what "exit status" means.
COMPILER
Translates the whole C source into object code once, before any run. Reports syntax errors at this stage.
TEXT EDITOR
Where you write the source — it stores characters, nothing more. Compilers never run your code for you.
atom 09 · languages

THREE LANGUAGE LEVELS

one task, three languages — A = B + C
/* 3 · HIGH-LEVEL — human-readable */
int a, b, c;
a = b + c;

/* 2 · ASSEMBLY — one mnemonic per
      machine instruction          */
        MOV  eax, [b]
        ADD  eax, [c]
        MOV  [a], eax

/* 1 · MACHINE — pure binary, the only
      thing the CPU understands     */
        10111000 00000001
        00000000 00000000
        00000011 00000101
        00000000 00000000
MACHINE
CPU's native tongue. Fast, impossible to read or maintain. Different for every processor family.
ASSEMBLY
Symbolic machine code — mnemonics instead of bits. Still one-to-one with hardware; still processor-specific.
HIGH-LEVEL — C
One statement = many machine instructions. Portable across machines, close enough to hardware to stay fast. This course lives here.
PORTABILITY
The same C source compiles on a laptop, a phone, and a washing machine — each compiler emits the right machine code for its CPU.

atom 13 · step 2 of 7

DESIGN — LOGIC BEFORE SYNTAX

  • Output of this step — an algorithm in pseudocode and/or a flowchart, correct and complete, still language-free.
  • Work top-down — sketch the big phases, then refine each until every step is one action: read, compute, compare, print.
  • Spot the decisions — overtime or not? valid or invalid? Each becomes a decision node.
  • Spot the repetition — per employee? until sentinel? Each becomes a loop.
  • Desk-check on paper — trace with sample numbers before touching a keyboard.
payroll — design sketch
ALGORITHM GrossPay

read  hours, rate
if hours > 40 then
    pay ← 40×rate + (hours−40)×rate×1.5
else
    pay ← hours×rate
endif
print pay
stop

/* one decision found → one IF
   no repetition in this problem  */

CEREMONY AROUND THE LOGIC
C needs scaffolding the design didn't: #include, main(), declarations for every variable, and a return. Learn the skeleton once, reuse forever.
payroll.c — design becomes code
#include <stdio.h>        // scaffolding
int main(void)
{
    double hours, rate, pay; // declarations

    printf("Hours> ");         // read
    scanf("%lf", &hours);
    printf("Rate> ");
    scanf("%lf", &rate);

    if (hours > 40.0)            // decision
        pay = 40.0*rate
            + (hours-40.0)*rate*1.5;
    else
        pay = hours * rate;

    printf("Pay = %.2f\n", pay);
    return (0);                // exit
}

Preprocessor
Text substitutions only: pastes in stdio.h, replaces #define names with values. Knows nothing about C grammar.
Compiler
Checks syntax + semantics — undeclared variables, type errors — then emits assembly. Errors here stop the build.
Assembler
Mnemonic → binary. Produces object code: machine code with unresolved external names.
Linker
Glues your object code to library code (printf's real body) — resolving names into addresses.
Loader
At run time: copies the executable into RAM, sets up the stack, jumps to main.

atom 16 · step 5 of 7

TEST — THREE CLASSES OF ERROR

Class Detected Example
Syntax compiler missing ; · scan for scanf · unbalanced { }
Runtime during execution ÷ by zero · reading letters where numbers expected
Logic only by you avg = a + b + c / 3; — precedence bug, compiles & runs, wrong answer
test-plan.txt — payroll
normal:    40h × 10      → 400.00
overtime:  45h × 10      → 475.00
boundary:  40h exactly   → 400.00  ✓ edge
boundary:  41h           → 415.00  ✓ edge
extreme:   0h × 10       →   0.00
invalid:   −5h           → ? (design said re-ask)
NORMAL CASES
Typical values — the path users walk daily. Verifies the core logic.
BOUNDARY CASES
Exactly at the edges — 40 hours, empty input, largest value. Most bugs hide here.
INVALID CASES
Data the program should reject. Tests the guards, not the math.
⚠ REGRESSION
After any fix, re-run all tests — a fix for one case can silently break another.

atom 18 · algorithms

ALGORITHM — DEFINITION

DEFINITION
An algorithm is a finite, ordered, unambiguous sequence of elementary steps that transforms given inputs into the required outputs and halts.

Five properties — each is a veto:

1 · Input
Zero or more quantities supplied beforehand.
2 · Output
At least one result — no output, no problem solved.
3 · Definiteness
Every step is exact — "add 5 to x", never "improve x".
4 · Finiteness
Terminates after a finite number of steps. Loop forever = not an algorithm.
5 · Effectiveness
Each step basic enough to be performed exactly and in finite time.
RECIPE ANALOGY
Ingredients = input, the dish = output, numbered steps = the algorithm. A recipe missing baking time (finiteness) or saying "cook until it seems right" (definiteness) fails the same tests.
algorithm vs program
/* ALGORITHM — language-free */
max ← a
if b > max then max ← b

/* PROGRAM — algorithm + syntax
   + types + I/O machinery        */
if (b > max) max = b;

// one algorithm, infinitely many
// programs (C, Python, Java…)

atom 22 · structure

THE STRUCTURED THEOREM

BÖHM & JACOPINI, 1966
Any computable algorithm can be expressed using only three control structures — sequence, selection, and repetition. No goto needed. Ever.
SEQUENCE
A then B then C — one entry, one exit.
SELECTION
if-then-else — choose one of two paths.
REPETITION
while — repeat while a condition holds.
SINGLE ENTRY, SINGLE EXIT
Each block is a black box: one way in, one way out. Nest black boxes freely — the whole program stays a single straight line of black boxes. That's what makes it provable and readable.
spaghetti vs structured
/* SPAGHETTI ✗ — flow jumps anywhere */
   goto retry;
   ...
retry:
   scanf("%d", &x);

/* STRUCTURED ✓ — shape of the code
      is the shape of the logic     */
   do {
       scanf("%d", &x);
   } while (x < 0);

/* "goto considered harmful"
   — Dijkstra, 1968 */
C EMBODIES THE THEOREM
C's if/else, while, for, do-while are factory-made building blocks of the three structures — modules M2 and M3 cover them atom by atom.
atom 23 · structure

TOP-DOWN DECOMPOSITION

  • Level 0 — state the whole problem in one sentence: "process the payroll for a department."
  • Level 1 — split into phases: read data → compute pay → print report.
  • Level 2 — split each phase: compute pay → regular pay + overtime pay − deductions.
  • Refine until atomic — every leaf is one verb: read hours, multiply rate by 1.5.
  • Solve leaves bottom-up — code the atoms, test them, assemble upward.
STEPWISE REFINEMENT
Each level is correct and complete for its level of detail. You never hold more complexity than one level at a time.
decomposition tree — payroll
PROCESS PAYROLL
├── READ DATA
│    ├── read employee id
│    ├── read hours worked
│    └── read hourly rate
├── COMPUTE PAY
│    ├── IF hours > 40
│    │    ├── regular = 40 × rate
│    │    └── extra = (h−40) × 1.5×rate
│    └── ELSE pay = h × rate
└── PRINT REPORT
     ├── print id
     └── print pay (2 decimals)

   interior nodes = compound blocks */

ATOM: #define

WHAT IT DOES
From this line onward, every occurrence of NAME in the file is textually replaced by value before compilation.
before → after preprocessing

#define MAX_HRS 40

DECLARATION — SYNTAX & SEMANTICS

type identifier_1, identifier_2, … ;
declaration.c
int    count;                /* one at a time */
double rate, pay, tax;         /* comma list */

WHAT THE COMPILER DOES
① Reserves sizeof(type) bytes ② Binds the name to that address ③ Records the type for later type checking. No executable code is generated — declarations are information, not action.
⚠ RULE: DECLARE BEFORE USE
In C89, every identifier must be declared before its first use, and all declarations come before statements in a block.
violate the rule

WHY THE RULE EXISTS
One-pass compilers read top to bottom — they must know a name's type the moment they meet it, to generate correct code immediately.

ATOM: printf()

printf anatomy

/* format string anatomy:
   ┌ literal text  → printed as-is
   ├ %.2f          → placeholder #1 ← pay

SHORT-CIRCUIT EVALUATION

THE RULE
&& stops at the first false — the whole thing is false, why continue? || stops at the first true — already true, why continue?
short-circuit.c
(x != 0) && (y / x > 2)
/* x == 0?  first part false →
   y/x NEVER EVALUATED →
   no division by zero!   */

(count > 0) || (total / count > 5)
/* count > 0? → true already,
   division never runs     */
⚠ ORDER IS A SAFETY FEATURE
Swap the operands — (y/x > 2) && (x != 0) — and the division crashes first. The guard must come before the guarded.
guard pattern — memorize this shape

             then do the work  */
if (divisor != 0 && limit / divisor > 2) {

SIDE-EFFECTS ARE SKIPPED TOO
0 && (i++) — the i++ never runs. If an operand has a side effect, short-circuiting decides whether it happens. Keep side effects out of conditions.
WHY C DOES THIS
Speed (skip needless work) and safety (guard idiom). It's a language feature with exactly one rule — learn it once, use it forever.

THE SENTINEL LOOP

scores.c
#define SENTINEL -1

sum = 0;  count = 0;
printf("score (-1 ends)> ");
scanf("%d", &score);          /* PRIME  */

while (score != SENTINEL) {
    sum   = sum + score;
    count = count + 1;
    scanf("%d", &score);      /* NEXT   */
}
avg = (double)sum / count;
SENTINEL CHOICE RULES
Must be impossible as real data (−1 for scores, 0 for a product ID, EOF for files) — and prominently documented in the prompt.

⚠ SENTINEL ≠ DATA
If −1 is a legal score, the loop eats it and stops early. Choose a sentinel outside the data's domain — that's the entire design decision.
WHY -1 GETS SKIPPED
The test != SENTINEL runs before the body — when −1 arrives, the condition is false and the body never sees it. Pre-test design pays off.

THE SECRET OF scanf
scanf returns the count of items read — 1 on success, 0 on mismatch, EOF (−1) when input ends. That return value is the loop condition.

    sum   += x;
    count += 1;

       (double)sum / count);

/* textbook form:
   while (scanf(...) != EOF)  */
PRIMING READ FOR FREE
The scanf is the test — value read and condition checked in one expression. No separate priming read needed; that's the elegance.

DEFINITION
A flag is an int variable acting as an event signal: 0 = not yet, 1 = it happened. The loop runs while (!flag) — until the event flips it.

and any loop is correct.

Q1 · Initialize
What are the control variable and every accumulator set to, before the first test? (identities! sum→0, product→1)
Q2 · Condition
What exactly continues the loop? When does it stop? What is true at exit — i = n+1? found? EOF?
Q3 · Update
What changes each pass so the loop provably approaches termination?
+ Body placement
What repeats — and what must stay outside (run once, not n times)?

GOAL : sum = 1+2+…+n

Q1 : sum = 0,  i = 1        ✓
Q2 : continue while i ≤ n
     exit when   i == n+1   ✓
Q3 : i = i + 1  (approaches n)   ✓
BODY: sum = sum + i  — nothing
      else belongs inside    ✓

Actual argument
The value passed at the call site: sal, r. Can be a variable, constant, or expression.
Formal parameter
The local variable that receives the copy: salary, rate. Exists only inside the function.
Pass by value
C copies the argument's value into the parameter. Changing salary inside does not change sal outside.
Return value
return (expr); sends one value back to the caller. The function's return type must match.
⚠ TYPE MISMATCH
If you pass an int where a double is expected, C silently promotes — but passing a double for an int parameter truncates. Watch the warnings.

POINTERS — & AND *

pointers.c — memory model
int x = 42;
int *p;       ← p is a pointer-to-int

p = &x;      ← p now holds ADDRESS of x

/* memory picture:
   name    addr     value
   ─────   ──────   ─────
    x      0x1000    42
    p      0x1008    0x1000  ← stores x's addr
*/

printf("%d\n",  x);    → 42
printf("%p\n",  p);    → 0x1000
printf("%d\n", *p);    → 42 (dereference)

*p = 99;               ← changes x to 99!
printf("%d\n",  x);    → 99
&x
Address-of operator — returns the memory address where x is stored. You've used it with scanf all along.
int *p
Declares p as a pointer to int — a variable that stores an address of an int.
*p
Indirection (dereference) — follows the address to access the value stored there. Read or write through the pointer.
⚠ UNINITIALIZED POINTER
Using *p before assigning p = &something accesses random memory — a crash or corruption. Always initialize pointers.
02 · pointers & modular

THE INDIRECTION OPERATOR

indirection.c
int    a = 10,  b = 20;
int   *pa = &a, *pb = &b;

/* read through pointer */
int sum = *pa + *pb;     → 30

/* write through pointer */
*pa = *pa + 5;           → a is now 15

/* redirect the pointer */
pa = &b;                 → pa now points to b
printf("%d\n", *pa);     → 20 (b's value)

/* pointer to double */
double  price = 9.99;
double *pp    = &price;
*pp = *pp * 1.10;        → 10% markup
TWO MEANINGS OF *
In a declaration, int *p means "p is a pointer." In an expression, *p means "follow the pointer to the value."
POINTER ARITHMETIC
*pa + *pb adds the values pointed to, not the addresses. *pa = *pa + 5 modifies the original variable through the pointer.
REDIRECTION
Changing pa = &b does NOT change a. It just makes pa point somewhere else — a different target.
⚠ * vs &
& goes from variable → address. * goes from address → variable. They are inverses: *(&x) == x.

Pass the address of the variable you want filled. Inside the function, use *param_p = value; to write through the pointer.

MULTIPLE CALLS WITH I/O PARAMS

multi_call.c
/* A function with BOTH input and output params */
void scale_and_shift(
    double  val,        ← input (copy)
    double  factor,     ← input (copy)
    double *result_p)   ← output (pointer)
{
    *result_p = val * factor + 1.0;
}

{
    double a, b, c;

    /* call 1 */
    scale_and_shift(3.0, 2.0, &a); → a = 7.0

    /* call 2: use output as next input */
    scale_and_shift(a,   0.5, &b); → b = 4.5

    /* call 3: same function, different data */
    scale_and_shift(b,   3.0, &c); → c = 14.5

    printf("%.1f  %.1f  %.1f\n", a, b, c);
    return (0);
}
CHAINING CALLS
The output of one call becomes the input of the next. The function is reused with different data each time — true modularity.
INPUT vs OUTPUT
Input params: passed by value (copy). Output params: passed by pointer (address). The * in the declaration is the giveaway.
⚠ SAME VARIABLE AS I/O
scale_and_shift(a, 2.0, &a) is legal — a is read (copied) as input, then overwritten as output. The copy happens first.

SCOPE OF NAMES

scope.c
#include <stdio.h>

int global_count = 0;  ← file scope (global)

void increment(void)
{
    int local = 10;     ← function scope
    global_count++;
    printf("local=%d, global=%d\n",
           local, global_count);
}

int main(void)
{
    int x = 5;          ← main's local

    increment();         → local=10, global=1
    increment();         → local=10, global=2

    /* printf("%d", local);  ← ERROR!
       local is NOT visible here */

    printf("x=%d\n", x); → x=5 unchanged
    return (0);
}
Local scope
Variables declared inside a function. Born at entry, destroyed at return. Invisible outside.
Block scope
Variables declared inside { } — even inside a loop or if. Destroyed when the block ends.
File (global) scope
Declared outside all functions. Visible everywhere below the declaration. Lasts the entire program.
Parameter scope
Formal parameters act as local variables inside their function.
⚠ AVOID GLOBALS
Global variables make debugging hard — any function can change them. Prefer local variables + parameters. Globals are a last resort.

OUTPUT PARAMS AS ACTUAL ARGS

       no & needed — val_p IS the address */

A pointer parameter is itself an address. You can pass it directly to another function that expects a pointer — no extra & needed.

Function B delegates to Function A, passing the same pointer. The final result flows all the way back to main — through a chain of pointer forwarding.
⚠ & of a POINTER
&val_p gives the address of the pointer variable, not the address it stores. This is a pointer-to-a-pointer — rarely what you want here.

LINEAR SEARCH

linear_search.c
/* search arr[0..n-1] for target
   return index if found, -1 if not */
int linear_search(int arr[], int n,
                  int target)
{
    for (int i = 0; i < n; i++) {
        if (arr[i] == target)
            return i;       ← found!
    }
    return -1;              ← not found
}

/* trace: arr = {3,7,1,9,4}, target = 9
   i=0: 3≠9  i=1: 7≠9  i=2: 1≠9
   i=3: 9==9 → return 3  ✓            */

/* usage */
int pos = linear_search(data, n, key);
if (pos == -1)
    printf("Not found\n");
else
    printf("Found at [%d]\n", pos);
O(n) — LINEAR TIME
Worst case: check every element. Best case: find it first. Average: n/2 comparisons. Simple but slow for large arrays.
UNSORTED OK
Works on any array — sorted or not. No preprocessing needed.
RETURN -1 CONVENTION
Since valid indices are 0..n-1, returning -1 is the standard "not found" signal. Always check the return value.
06 · searching

BINARY SEARCH

binary_search.c
/* REQUIRES sorted array */
int binary_search(int arr[], int n,
                  int target)
{
    int lo = 0, hi = n - 1;

    while (lo <= hi) {
        int mid = (lo + hi) / 2;

        if (arr[mid] == target)
            return mid;        ← found
        else if (arr[mid] < target)
            lo = mid + 1;       ← search right
        else
            hi = mid - 1;       ← search left
    }
    return -1;
}

/* trace: {2,5,8,12,16,23,38}, target=23
   lo=0 hi=6 mid=3: 12<23 → lo=4
   lo=4 hi=6 mid=5: 23==23 → return 5 ✓ */
O(log n) — LOGARITHMIC
Halves the search space each step. 1000 elements → ≤10 comparisons. 1,000,000 → ≤20. Enormously faster than linear.
⚠ MUST BE SORTED
Binary search on an unsorted array gives wrong results. Sort first, then search — or use linear search if unsorted.
HOW IT WORKS
Compare target to middle element. If equal → done. If target is larger → discard left half. If smaller → discard right half. Repeat.

BUBBLE SORT

bubble_sort.c
void bubble_sort(int arr[], int n)
{
    for (int i = 0; i < n-1; i++) {
        for (int j = 0; j < n-1-i; j++) {
            if (arr[j] > arr[j+1]) {
                /* swap adjacent */
                int temp = arr[j];
                arr[j]   = arr[j+1];
                arr[j+1] = temp;
            }
        }
    }
}

/* trace: {5,3,8,1,2}
pass 1: 3,5,1,2,|8|  (8 bubbles to end)
pass 2: 3,1,2,|5|    (5 settles)
pass 3: 1,2,|3|      (3 settles)
pass 4: 1,|2|        (done)             */
HOW IT WORKS
Compare adjacent elements. If out of order, swap. The largest value "bubbles" to the end on each pass. Repeat n-1 times.
O(n²) COMPLEXITY
Nested loops: outer runs n-1 times, inner shrinks by 1 each pass. Total ≈ n²/2 comparisons. Slow for large arrays, but easy to code and understand.
STABLE SORT
Equal elements keep their original order — useful when sorting by multiple criteria.

INSERTION SORT

insertion_sort.c
void insertion_sort(int arr[], int n)
{
    for (int i = 1; i < n; i++) {
        int key = arr[i];
        int j   = i - 1;

        /* shift larger elements right */
        while (j >= 0 && arr[j] > key) {
            arr[j+1] = arr[j];
            j--;
        }
        arr[j+1] = key;  ← insert
    }
}

/* trace: {5,3,8,1,2}
i=1: key=3  shift 5→   [3,5,8,1,2]
i=2: key=8  no shift    [3,5,8,1,2]
i=3: key=1  shift 8,5,3 [1,3,5,8,2]
i=4: key=2  shift 8,5,3 [1,2,3,5,8] ✓ */
CARD GAME ANALOGY
Like sorting a hand of cards: pick each card and insert it into the correct position among the already-sorted cards to its left.
O(n²) WORST, O(n) BEST
Worst case (reverse sorted): n²/2 shifts. Best case (already sorted): only n-1 comparisons, zero shifts. Great for nearly-sorted data.
SHIFT, NOT SWAP
Insertion sort shifts elements one position right, then inserts once. Fewer writes than bubble sort's repeated swaps.

SELECTION SORT

selection_sort.c
void selection_sort(int arr[], int n)
{
    for (int i = 0; i < n-1; i++) {
        int min_idx = i;

        /* find minimum in unsorted portion */
        for (int j = i+1; j < n; j++) {
            if (arr[j] < arr[min_idx])
                min_idx = j;
        }

        /* swap minimum with position i */
        int temp     = arr[i];
        arr[i]       = arr[min_idx];
        arr[min_idx] = temp;
    }
}

/* trace: {5,3,8,1,2}
i=0: min=1@[3] swap→ [1,3,8,5,2]
i=1: min=2@[4] swap→ [1,2,8,5,3]
i=2: min=3@[4] swap→ [1,2,3,5,8]
i=3: min=5@[3] no-op [1,2,3,5,8] ✓ */
HOW IT WORKS
Find the minimum in the unsorted portion. Swap it to the front. Repeat for the remaining unsorted portion.
O(n²) ALWAYS
Always does n²/2 comparisons, regardless of input order. But only n-1 swaps — fewest writes of the three basic sorts.
SORT COMPARISON
Bubble: simple, many swaps. Insertion: fast on nearly-sorted. Selection: fewest swaps, consistent performance. All O(n²).

   < 0  if a comes BEFORE b

if (strcmp(names[j], names[j+1]) > 0) {

    strcpy(names[j], names[j+1]);

}

Compares character by character using ASCII values. First difference decides the result. Uppercase letters (65-90) come before lowercase (97-122).

⚠ NEVER USE ==
str1 == str2 compares pointer addresses, not string content. Two strings with identical text at different addresses would be "not equal."

01 · recursion

THE NATURE OF RECURSION

  • Recursion — a function that calls itself, directly or indirectly. The function solves a smaller version of the same problem, then combines results.
  • Base case — the simplest input that can be answered without recursion. It stops the chain of calls. Without it: infinite recursion → stack overflow.
  • Recursive step — reduces the problem toward the base case and calls itself. Each call must make progress.
  • Divide and conquer — break a big problem into smaller identical sub-problems, solve each recursively, combine.
countdown.c — simplest recursion
void countdown(int n)
{
    if (n <= 0) {              ← BASE CASE
        printf("Go!\n");
        return;
    }
    printf("%d...\n", n);
    countdown(n - 1);         ← RECURSIVE CALL
}

/* countdown(3) produces:
   3...
   2...
   1...
   Go!

   3 calls countdown(2)
   2 calls countdown(1)
   1 calls countdown(0) → base case */
02 · recursion

TRACING — STACK FRAMES

factorial — stack trace
int factorial(int n)
{
    if (n <= 1) return 1;          ← base
    return n * factorial(n - 1);   ← recurse
}

/* call factorial(4) — stack grows DOWN */

┌─────────────────────────┐
│ factorial(4)              │ n=4
│   return 4 * factorial(3)│
├─────────────────────────┤
│ factorial(3)              │ n=3
│   return 3 * factorial(2)│
├─────────────────────────┤
│ factorial(2)              │ n=2
│   return 2 * factorial(1)│
├─────────────────────────┤
│ factorial(1)              │ n=1
│   return 1  ← base case   │
└─────────────────────────┘

/* unwind: 1 → 2*1=2 → 3*2=6 → 4*6=24 */
STACK FRAME
Each recursive call creates a new stack frame with its own copy of n. The frames accumulate until the base case.
WINDING
Calls go deeper: 4→3→2→1. Each waits for the result of the next. The base case returns first.
UNWINDING
Results propagate back: 1→2→6→24. Each frame multiplies its n by the returned value and sends it up.
⚠ STACK OVERFLOW
Too-deep recursion exhausts stack memory. factorial(100000) would crash. Use iteration for very deep computations.
03 · recursion

RECURSIVE MATH FUNCTIONS

recursive_math.c
/* FACTORIAL: n! = n × (n-1)! */
int fact(int n) {
    if (n <= 1) return 1;
    return n * fact(n - 1);
}

/* POWER: x^n = x × x^(n-1) */
double power(double x, int n) {
    if (n == 0) return 1.0;
    return x * power(x, n - 1);
}

/* FIBONACCI: f(n) = f(n-1) + f(n-2) */
int fib(int n) {
    if (n <= 0) return 0;
    if (n == 1) return 1;
    return fib(n-1) + fib(n-2);
}

/* GCD: Euclid's algorithm */
int gcd(int a, int b) {
    if (b == 0) return a;
    return gcd(b, a % b);
}
MATHEMATICAL DEFINITION
Many math functions are defined recursively. The code mirrors the definition directly — elegant and provably correct.
⚠ FIBONACCI IS SLOW
Naive fib(n) has O(2ⁿ) time — it recomputes the same values exponentially. fib(40) takes seconds. Use iteration or memoization for large n.
GCD — ELEGANT
Euclid's algorithm: gcd(a,b) = gcd(b, a%b). Base: b==0 → return a. Runs in O(log n) steps — recursion done right.
04 · recursion

RECURSION WITH ARRAYS

recursive_array.c
/* SUM of array elements */
int array_sum(int arr[], int n)
{
    if (n <= 0) return 0;       ← base
    return arr[n-1] + array_sum(arr, n-1);
}
/* sum({3,5,2}, 3)
   = 2 + sum({3,5,2}, 2)
   = 2 + 5 + sum({3,5,2}, 1)
   = 2 + 5 + 3 + sum({3,5,2}, 0)
   = 2 + 5 + 3 + 0 = 10              */

/* FIND MAX in array */
int array_max(int arr[], int n)
{
    if (n == 1) return arr[0];
    int rest_max = array_max(arr, n-1);
    return (arr[n-1] > rest_max)
           ? arr[n-1] : rest_max;
}
THE PATTERN
Process the last element, then recursively process the rest (n-1 elements). Base case: empty array or single element.
SHRINKING RANGE
Each call decrements n. The array itself is unchanged — only the "window" shrinks. The pointer stays the same.
RECURSION vs LOOP
A loop is simpler and faster for array traversal. Recursion is elegant but has function-call overhead per element. Choose based on clarity vs. performance.
05 · recursion

RECURSION WITH STRINGS

recursive_string.c
/* recursive string length */
int my_strlen(char *s)
{
    if (*s == '\0') return 0;   ← base
    return 1 + my_strlen(s + 1); ← next char
}

/* reverse print */
void print_reverse(char *s)
{
    if (*s == '\0') return;
    print_reverse(s + 1);   ← recurse first
    printf("%c", *s);       ← print on unwind
}
/* print_reverse("CAT") → TAC */

/* check palindrome */
int is_palindrome(char *s, int lo, int hi)
{
    if (lo >= hi) return 1;
    if (s[lo] != s[hi]) return 0;
    return is_palindrome(s, lo+1, hi-1);
}
BASE CASE: \0
The null terminator is the natural base case for string recursion. When *s == '\0', the string is empty — stop.
POINTER ARITHMETIC
s + 1 moves to the next character. Each recursive call processes a shorter string — one char closer to \0.
ORDER MATTERS
print_reverse: recurse before printing → prints in reverse order. Recurse after printing → prints forwards. The placement changes behavior.
PALINDROME TRICK
Compare first and last chars. If equal, recurse on the substring s[lo+1..hi-1]. Base: indices cross → it's a palindrome.

USER-DEFINED STRUCTURE TYPES

struct.c
/* define a structure type */
typedef struct {
    char   name[50];
    int    id;
    double gpa;
} student_t;

int main(void)
{
    /* declare and initialize */
    student_t s1 = {"Alice", 1001, 3.85};

    /* access with dot operator */
    printf("Name: %s\n", s1.name);
    printf("ID:   %d\n", s1.id);
    printf("GPA:  %.2f\n", s1.gpa);

    /* modify a member */
    s1.gpa = 3.90;

    /* copy entire struct */
    student_t s2 = s1;  ← copies all members

    return (0);
}
struct
Groups different types under one name. A student has a name (char[]), an id (int), and a gpa (double).
typedef
Creates a type alias: student_t instead of struct student. Shorter, cleaner code.
Dot operator (.)
s1.name accesses the name member. Each member is like an independent variable.
Assignment (=)
Unlike arrays, structs CAN be assigned with =. Every member is copied. This is a deep copy for scalar members.
⚠ NO == FOR STRUCTS
You cannot compare structs with ==. Compare member by member, or write a comparison function.
02 · structures

STRUCTURES AS PARAMETERS

struct_params.c
/* INPUT parameter — pass by value (copy) */
void print_student(student_t s)
{
    printf("%s (ID:%d) GPA:%.2f\n",
           s.name, s.id, s.gpa);
}

/* OUTPUT parameter — pass by pointer */
void read_student(student_t *sp)
{
    printf("Name> ");
    scanf("%s", sp->name);  ← arrow!
    printf("ID>   ");
    scanf("%d", &sp->id);
    printf("GPA>  ");
    scanf("%lf", &sp->gpa);
}

/* usage */
student_t s;
read_student(&s);      ← fills s
print_student(s);      ← reads s
ARROW OPERATOR (→)
When you have a pointer to a struct, use sp->member instead of (*sp).member. Same thing, cleaner syntax.
BY VALUE = COPY
print_student(s) copies the entire struct onto the stack. Safe (original unchanged) but expensive for large structs.
BY POINTER = MODIFY
read_student(&s) passes the address. The function fills the caller's struct through the pointer. Efficient and necessary for output.
⚠ EFFICIENCY TIP
For large structs used as input only, pass a const pointer: void print(const student_t *sp) — no copy, no accidental modification.
03 · structures

FUNCTIONS RETURNING STRUCTURES

struct_return.c
typedef struct {
    double x, y;
} point_t;

/* return a struct by value */
point_t make_point(double x, double y)
{
    point_t p;
    p.x = x;
    p.y = y;
    return p;   ← copy returned
}

/* compute midpoint */
point_t midpoint(point_t a, point_t b)
{
    return make_point(
        (a.x + b.x) / 2.0,
        (a.y + b.y) / 2.0
    );
}

/* usage */
point_t p1 = make_point(1.0, 2.0);
point_t p2 = make_point(5.0, 8.0);
point_t m  = midpoint(p1, p2);
/* m.x = 3.0, m.y = 5.0 */
CONSTRUCTOR PATTERN
make_point(x, y) acts like a constructor — creates and returns a struct. Clean, readable, reusable.
COMPOSABILITY
midpoint takes two points, returns a point. Functions that accept and return structs compose naturally — building complex logic from simple pieces.
⚠ RETURN = COPY
Returning a struct copies it. For small structs (point, complex number) this is fine. For large structs, consider output pointers instead.

05 · unions

UNION TYPES

union.c
/* union: ALL members SHARE the same memory */
typedef union {
    int    i;      ← 4 bytes
    double d;      ← 8 bytes
    char   c;      ← 1 byte
} value_t;
/* sizeof(value_t) = 8 (size of largest) */

value_t v;
v.i = 42;             ← store as int
printf("%d\n", v.i);   → 42 ✓

v.d = 3.14;            ← OVERWRITES i!
printf("%.2f\n", v.d); → 3.14 ✓
printf("%d\n", v.i);   → garbage!

/* tagged union — track which is active */
typedef struct {
    int  tag;    /* 0=int, 1=double, 2=char */
    value_t val;
} tagged_t;
SHARED MEMORY
All union members overlap in memory. Only one member is valid at a time. Size = size of the largest member.
struct vs union
struct: members are side by side (all active). union: members are stacked on top (one active). Struct size = sum; union size = max.
TAGGED UNION
Wrap the union in a struct with a tag field that records which member is currently valid. The safe way to use unions.
⚠ READING WRONG MEMBER
Writing v.d = 3.14 then reading v.i gives garbage — the bit pattern of a double interpreted as an int. Always track the active member.

Feature struct union
Members all coexist, separate memory share same memory location
Active all members at once only ONE at a time
Size sum of all members (+padding) size of largest member
Use case group related data save memory, variant types
Assignment copies all members copies the entire block
Safety always safe to read any member must track active member

01 · text files

FILE I/O — fopen & fclose

file_io.c
#include <stdio.h>

int main(void)
{
    FILE *fp;

    /* open for writing */
    fp = fopen("data.txt", "w");
    if (fp == NULL) {
        printf("Error opening file!\n");
        return (1);
    }

    fprintf(fp, "Score: %d\n", 95);
    fprintf(fp, "Name: %s\n", "Alice");
    fclose(fp);

    /* open for reading */
    fp = fopen("data.txt", "r");
    char line[100];
    while (fgets(line, 100, fp) != NULL)
        printf("%s", line);
    fclose(fp);

    return (0);
}
ModePurposeCreates?
"r"read textNo — error if missing
"w"write textYes — truncates if exists
"a"append textYes — adds to end
"rb"read binaryNo
"wb"write binaryYes — truncates
⚠ ALWAYS CHECK fopen
fopen returns NULL on failure (file not found, permission denied). Using a NULL file pointer crashes the program.
ALWAYS fclose
Unflushed data may be lost. fclose writes buffers to disk and releases the file handle. One fclose per fopen.

FORMATTED FILE I/O

/* fprintf — write formatted data to file */
FILE *out = fopen("grades.txt", "w");

    fprintf(out, "%s %d %.2f\n",

FILE *in = fopen("grades.txt", "r");

while (fscanf(in, "%s %d %lf",

{

           name, id, gpa);
}

/* fscanf returns number of items read
   or EOF at end of file               */
fprintf = printf TO FILE
Same format strings, same placeholders — but first argument is the FILE * instead of stdout. fprintf(stdout, ...) = printf(...).
fscanf RETURN VALUE
Returns the number of items successfully read. Check == expected_count to detect end-of-file or malformed input.
TEXT FORMAT
Data is stored as human-readable characters. 42 becomes the characters '4' and '2'. Editable with any text editor, but larger than binary.
⚠ fscanf & STRINGS
%s stops at whitespace. For names with spaces, use fgets and parse manually, or use a delimiter format.
03 · binary files

BINARY FILES

binary.c
typedef struct {
    int id; char name[30]; double balance;
} account_t;

/* WRITE array of structs to binary file */
account_t accts[3] = {
    {101, "Alice", 5000.00},
    {102, "Bob",   3200.50},
    {103, "Carol", 8750.25}
};

FILE *fp = fopen("accts.bin", "wb");
fwrite(accts, sizeof(account_t), 3, fp);
fclose(fp);

/* READ back */
account_t buf[3];
fp = fopen("accts.bin", "rb");
fread(buf, sizeof(account_t), 3, fp);
fclose(fp);

printf("%s: $%.2f\n", buf[1].name,
       buf[1].balance);  → Bob: $3200.50
fwrite(ptr,sz,n,fp)
Write n items, each sz bytes, from memory at ptr to file fp.
fread(ptr,sz,n,fp)
Read n items of sz bytes from file into memory. Returns number of items actually read.
TEXT vs BINARY
Text: human-readable, portable, larger. Binary: exact memory image, compact, fast, but not human-readable and platform-dependent.
⚠ PORTABILITY
Binary files depend on struct layout, byte order, and padding. A binary file written on one machine may not read correctly on another with different architecture.
04 · binary files

RANDOM ACCESS

random_access.c
/* jump to specific record in binary file */
FILE *fp = fopen("accts.bin", "rb");

/* read the 3rd record (index 2) */
fseek(fp, 2 * sizeof(account_t), SEEK_SET);
account_t rec;
fread(&rec, sizeof(account_t), 1, fp);

/* ftell — current position in bytes */
long pos = ftell(fp);
printf("Position: %ld bytes\n", pos);

/* rewind — go back to start */
rewind(fp);  /* same as fseek(fp,0,SEEK_SET) */

/* fseek origins:
   SEEK_SET  — from beginning
   SEEK_CUR  — from current position
   SEEK_END  — from end of file       */

/* modify record in place */
fp = fopen("accts.bin", "r+b");
fseek(fp, 1 * sizeof(account_t), SEEK_SET);
rec.balance = 9999.99;
fwrite(&rec, sizeof(account_t), 1, fp);
fclose(fp);
DIRECT ACCESS
With fixed-size records, fseek(fp, index * sizeof(record), SEEK_SET) jumps directly to any record — O(1) access, no scanning.
UPDATE IN PLACE
Open with "r+b", seek to the record, write the new data. The file size doesn't change — just the bytes at that position.
FILE POSITION
ftell(fp) returns the current byte offset. After reading one record, it advances by sizeof(record) bytes.
⚠ TEXT vs BINARY SEEK
fseek with byte offsets only works reliably on binary files. In text mode, line endings may be translated, making byte counts unreliable.
05 · database

SEARCHING A DATABASE

db_search.c
/* sequential search in a binary file */
int find_account(FILE *fp, int target_id,
                 account_t *result)
{
    account_t rec;
    rewind(fp);

    while (fread(&rec, sizeof(account_t),
                 1, fp) == 1)
    {
        if (rec.id == target_id) {
            *result = rec;
            return 1;    ← found
        }
    }
    return 0;              ← not found
}

/* usage */
account_t a;
if (find_account(fp, 102, &a))
    printf("%s: $%.2f\n", a.name, a.balance);
else
    printf("Account not found\n");
SEQUENTIAL FILE SEARCH
Read records one by one from the file until the target is found or EOF is reached. O(n) — must check every record in the worst case.
BINARY SEARCH ON FILE
If the file is sorted by key, use fseek to jump to the middle record, compare, and halve the search space — O(log n) disk reads.
LOAD vs STREAM
Small DB: load entire file into an array, search in memory. Large DB: stream from disk, process one record at a time to save RAM.
⚠ FILE MUST BE OPEN
The FILE * must remain open during the search. Don't close and reopen between reads — use rewind to restart.
06 · searching

LINEAR SEARCH — ANALYSIS

linear_search.c
int linear_search(int arr[], int n,
                  int target)
{
    for (int i = 0; i < n; i++)
        if (arr[i] == target)
            return i;
    return -1;
}
CaseComparisonsComplexity
Best1 (found at [0])O(1)
Averagen/2O(n)
Worstn (not found)O(n)
WHEN TO USE
Unsorted data, small arrays, or when you need to search once. No preprocessing required.
SENTINEL VARIANT
Place the target at arr[n] as a sentinel — eliminates the i < n check each iteration. Slightly faster inner loop, same O(n).
SCALING
1,000 items: ~500 avg comparisons. 1,000,000 items: ~500,000. For large sorted data, binary search is orders of magnitude faster.

BINARY SEARCH — ANALYSIS

binary_search.c
int binary_search(int arr[], int n,
                  int target)
{
    int lo = 0, hi = n - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (arr[mid] == target) return mid;
        else if (arr[mid] < target) lo = mid+1;
        else hi = mid-1;
    }
    return -1;
}

1,00010
1,000,00020

O(log₂ n)
Each comparison eliminates half the remaining elements. Doubling the array size adds only ONE more comparison.
OVERFLOW-SAFE MID
mid = lo + (hi - lo) / 2 avoids integer overflow that (lo + hi) / 2 can cause when both are large.
⚠ MUST BE SORTED
Binary search on an unsorted array is undefined — it may return wrong results or miss existing elements. Sort first (one-time O(n log n) cost).
08 · sorting

BUBBLE SORT — ANALYSIS

bubble_sort.c — optimized
void bubble_sort(int arr[], int n)
{
    for (int i = 0; i < n-1; i++) {
        int swapped = 0;
        for (int j = 0; j < n-1-i; j++) {
            if (arr[j] > arr[j+1]) {
                int t = arr[j];
                arr[j] = arr[j+1];
                arr[j+1] = t;
                swapped = 1;
            }
        }
        if (!swapped) break; ← early exit
    }
}

/* trace: {4,2,3,1}
pass 1: 2,3,1,|4|  (3 swaps)
pass 2: 2,1,|3|    (1 swap)
pass 3: 1,|2|      (1 swap)  done ✓ */
CaseComparisonsSwaps
Best (sorted)n-10
Averagen²/4n²/4
Worst (reverse)n²/2n²/2
OPTIMIZATION
The swapped flag detects if no swaps occurred — array is already sorted. Best case drops from O(n²) to O(n).
VERDICT
Simple to understand and code. Too slow for large data. Good for educational purposes and very small arrays.

INSERTION SORT — ANALYSIS

insertion_sort.c
void insertion_sort(int arr[], int n)
{
    for (int i = 1; i < n; i++) {
        int key = arr[i];
        int j = i - 1;
        while (j >= 0 && arr[j] > key) {
            arr[j+1] = arr[j];
            j--;
        }
        arr[j+1] = key;
    }
}

/* trace: {4,2,3,1}
i=1: key=2, shift 4→     [2,4,3,1]
i=2: key=3, shift 4→     [2,3,4,1]
i=3: key=1, shift 4,3,2→ [1,2,3,4] ✓ */
CaseComparisonsShifts
Best (sorted)n-10
Averagen²/4n²/4
Worst (reverse)n²/2n²/2
ADAPTIVE
O(n) for nearly sorted data — few elements are far from their correct position, so few shifts needed. The best simple sort for "almost sorted" input.
ONLINE
Can sort data as it arrives — no need to know the total count upfront. Each new element is inserted into the correct position immediately.
VERDICT
Best of the O(n²) sorts for practical use. Preferred for small arrays (n < 50) and nearly-sorted data. Used as a subroutine in advanced sorts.
10 · sorting

SELECTION SORT — ANALYSIS

selection_sort.c
void selection_sort(int arr[], int n)
{
    for (int i = 0; i < n-1; i++) {
        int min = i;
        for (int j = i+1; j < n; j++)
            if (arr[j] < arr[min])
                min = j;
        if (min != i) {
            int t = arr[i];
            arr[i] = arr[min];
            arr[min] = t;
        }
    }
}

/* trace: {4,2,3,1}
i=0: min=1@[3] swap→ [1,2,3,4]
i=1: min=2@[1] no-op
i=2: min=3@[2] no-op  done ✓ */
CaseComparisonsSwaps
Bestn²/20
Averagen²/2n/2
Worstn²/2n-1
FEWEST SWAPS
At most n-1 swaps — one per outer pass. Best choice when swaps are expensive (e.g., large records, slow memory).
CONSISTENT
Always does n²/2 comparisons, regardless of input order. No best-case speedup like insertion sort — but predictable performance.
VERDICT
Simple, minimal memory writes. Not adaptive. Use when write cost dominates or for very small arrays.
11 · comparison

SORTING COMPARISON

Algorithm Best Average Worst Stable? Swaps
Bubble O(n) O(n²) O(n²) Yes Many
Insertion O(n) O(n²) O(n²) Yes Moderate
Selection O(n²) O(n²) O(n²) No Fewest
SPACE COMPLEXITY
All three are in-place — O(1) extra memory. They sort the array directly, no auxiliary array needed.
CHOOSE WISELY
Nearly sorted? → Insertion. Expensive swaps? → Selection. Teaching? → Bubble. Large data? → Use qsort() from stdlib.h (O(n log n)).
STABLE SORT
A sort is stable if equal elements keep their original order. Important when sorting by multiple criteria (e.g., sort by name, then by grade).
THE BIG PICTURE
These three are introductory sorts. Real-world programs use O(n log n) algorithms like quicksort, mergesort, or heapsort. But understanding O(n²) sorts builds the foundation.
