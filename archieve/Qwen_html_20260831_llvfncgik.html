UNIT II · top-down design with functions

BUILDING PROGRAMS FROM EXISTING INFORMATION

Never solve the same problem twice. A program is built by calling pieces that already exist — from the library or written by you — and wiring them together in main().

/* reinvent ✗ — fragile, unreadable */
double root = 1.41421356;   /* hard-coded! */
double area = 3.14159 * r * r;

/* reuse ✓ — the library does it  */
#include <math.h>
double root = sqrt(2.0);
double area = PI * pow(radius, 2);

What reuse buys you

  • Reliability — library code is tested by millions of runs
  • Abstraction — think what (area), not how (formula)
  • Modularity — small pieces, independently testable
  • Teamwork — split modules between programmers
  • Shorter code — one call replaces twenty lines
ABSTRACTION — a function call hides every internal step. The caller only needs three facts: name, arguments in, result out.

UNIT II · top-down design with functions

TOP-DOWN DESIGN & STRUCTURE CHARTS

The method

  1. State the whole task as one module.
  2. Split it into sub-tasks — each one verb + one object (get_data, compute_pay, print_pay).
  3. Split again, until every leaf is directly codeable.
  4. Draw the structure chart before any code.

Chart rules

  • one box = exactly one function
  • arrows point down: caller → called
  • children together do the parent's job
  • siblings don't talk to each other — only through the parent

UNIT II · top-down design with functions

ANATOMY OF A USER-DEFINED FUNCTION

Every function exists in three places: the prototype (promise), the definition (body), and the call (use).

/* 1 · PROTOTYPE — before main, ends with ; */
void print_banner(void);

int main(void)
{
    print_banner();                  /* 3 · CALL — jumps to definition   */
    printf("Step 1: read data\n");
    print_banner();                  /*    runs again, from the top      */
    return (0);                      /*    resumes here after each call  */
}

/* 2 · DEFINITION — the actual work       */
void print_banner(void)
{
    printf("=====================\n");
    printf("   PAYROLL SYSTEM      \n");
    printf("=====================\n");
}
⚠ PROTOTYPE FIRST — without it the compiler meets the call blind and cannot check argument count/type. Declare every function before you call it.

UNIT III · pointers & modular programming

MEMORY & ADDRESSES

RAM is a street of numbered cells. Every variable occupies cells; the cell number is its address. Every variable therefore has four facts: name, type, value, address.

RAM (zoomed in)
 address │  1000          1008         1016
         │  hours = 20.0  rate = 7.5   pay = 150.0
         └────────── doubles: 8 bytes each ──────────▶
  • an address is just a number — so it can be stored in a variable
  • a variable that stores an address is called a pointer
  • addresses let a function say: "here is where your data lives — work on it directly"
double hours = 20.0;
double *hp;              /* hp will hold the address
                            of a double            */
hp = &hours;             /* hp ← 1000 (the address) */
THE BIG IDEA — Unit II passed values (copies). Unit III passes addresses (the real thing). That one change unlocks output parameters, arrays, strings and files.
UNIT III · pointers & modular programming

POINTERS & THE INDIRECTION OPERATOR

Two operators rule everything: & means "give me the address of", * means "go to the address and use the value there".

int  x = 5, y;
int *p;                  /* pointer to int */

p  = &x;                 /* p ← address of x   */
y  = *p;                 /* y ← 5  (read thru p) */
*p = 9;                  /* x is now 9 (write!)  */

printf("%d",  x);        /* 9 */
printf("%d", *p);        /* 9 — same cell */
declaration   int *p;     "p may hold the address of an int"
&x            address-of  → the number of the cell
*p            dereference → the value inside the cell

   p ─────────▶  x  (5)
      points at
  • int *p; — the * binds to the name: p is "pointer to int"
  • *p and x are now two names for the same memory cell — writing one changes the other
⚠ WILD POINTERS — an uninitialized pointer points anywhere. *p = 9; on it corrupts unknown memory. Always initialize: int *p = &x; or int *p = NULL;
UNIT III · pointers & modular programming

FUNCTIONS WITH OUTPUT PARAMETERS

C passes arguments by value — a function only ever gets copies, so it cannot change the caller's variables… unless it is given their addresses.

/* OUTPUT params: caller hands over addresses */
void get_two(double *a_ptr, double *b_ptr)
{
    printf("Enter two numbers> ");
    scanf("%lf", a_ptr);   /* already an address */
    scanf("%lf", b_ptr);   /* no & needed here   */
}

int main(void)
{
    double x, y;
    get_two(&x, &y);       /* & — give the address */
    printf("%.1f %.1f\n", x, y);   /* changed! */
    return (0);
}
main:  x ?        y ?
        ▲          ▲
        │&x        │&y
   a_ptr┘     b_ptr┘
get_two writes INTO x and y
THE scanf MYSTERY SOLVED — scanf("%lf", &miles) needs & because scanf must write into your variable; it can only do that if it receives the address. That is exactly the output-parameter pattern.
UNIT III · pointers & modular programming

swap — BY VALUE ✗ vs BY POINTER ✓

/* ✗ swaps COPIES — m, n untouched */
void swap_bad(int a, int b)
{
    int t = a;
    a = b;          /* copies only */
    b = t;
}
swap_bad(m, n);     /* m, n unchanged */
/* ✓ swaps the caller's variables  */
void swap(int *a, int *b)
{
    int t = *a;     /* read  the cells */
    *a = *b;        /* write the cells */
    *b = t;
}
swap(&m, &n);       /* m, n really swap */
before:  m = 3     n = 7            after swap(&m, &n):
copies version:  m = 3  n = 7  ✗    pointer version:  m = 7  n = 3  ✓
⚠ THE GOLDEN RULE — if a function must change a caller's variable, the caller must pass &variable and the function must receive type *parameter. Forgetting either side breaks it silently.
UNIT III · pointers & modular programming

MULTIPLE CALLS · INPUT/OUTPUT PARAMETERS

One function, called many times, can feed different data in and accumulate results out — the same pointer parameters aim at different cells on each call.

/* input: s (value) · output: sum, n (addresses) */
void add_score(double s, double *sum, int *n)
{
    *sum = *sum + s;      /* update caller's total */
    *n   = *n + 1;        /* update caller's count */
}

int main(void)
{
    double sum = 0.0, score, avg;
    int n = 0, i;

    for (i = 0; i < 5; i = i + 1) {
        scanf("%lf", &score);
        add_score(score, &sum, &n);   /* 5 calls, one pair of accumulators */
    }
    avg = sum / n;
    printf("Average = %.2f\n", avg);
    return (0);
}
PATTERN — initialize accumulators in the caller, pass their addresses, update through * inside. State lives outside; the function stays pure and reusable.
UNIT III · pointers & modular programming

SCOPE OF NAMES

Scope = the region of the program where a name is visible. Lifetime = how long the storage exists.

scopedeclaredvisiblelifetime
block (local)inside { }from declaration to the closing }while the block runs
file (global)outside all functionsfrom declaration to end of filewhole program run
int total = 0;               /* GLOBAL — visible everywhere below */

void bump(int step)
{
    int total = 5;           /* LOCAL — SHADOWS the global        */
    total = total + step;    /* touches only the local copy       */
}                            /* local total dies here; global is still 0 */
  • same name, two variables — the inner one wins inside its block
  • each function call gets fresh locals
  • parameters are locals of that function
⚠ GLOBALS — any function can read/write them, so bugs hide anywhere. Prefer locals + parameters; use globals only for truly program-wide constants.
UNIT III · pointers & modular programming

FORMAL OUTPUT PARAMETERS AS ACTUAL ARGUMENTS

A pointer received as a formal parameter can itself be passed on as the actual argument of another call — no &, no *. Addresses flow down the chain.

void read_one(double *p)                 /* lowest level  */
{
    scanf("%lf", p);
}

void read_pair(double *p1, double *p2)   /* middle level  */
{
    read_one(p1);     /* formal pointer → actual argument */
    read_one(p2);
}

int main(void)
{
    double x, y;
    read_pair(&x, &y);                   /* top level     */
    printf("%.1f %.1f\n", x, y);
    return (0);
}
main: &x ──▶ p1 ──▶ read_one's p ──▶ scanf writes into x
one address, three levels — nobody needs to know x exists
WHY — this is how layered programs stay generic: each level just forwards addresses. It is also exactly how library functions chain together.

DECLARING & REFERENCING ARRAYS

An array = many values of the same type, one name, chosen by an index.

#define N 7

int small[3]  = {5, 9, 2};  /* initializer list */

temps[0] = 30.5;            /* first element    */

temps in memory — CONTIGUOUS cells:
 index:  [0]    [1]    [2]    [3]    [4]    [5]    [6]
       30.5    ..     ..     ..     ..     ..    28.0
        ▲ first                       last ▲ (N-1, NOT N!)

  • indices run 0 … N−1 — C counts from zero

UNIT IV · arrays

ARRAY SUBSCRIPTS

a[i] — the subscript is any integer expression: constant, variable, or formula.

i = 3;
small[i]       = 7;                /* small[3]           */
small[i - 1]   = small[i] + 2;     /* small[2] ← 9       */
scanf("%d", &small[i]);            /* read into small[3] */
printf("%d", small[2 * i - 6]);    /* small[0]           */

The bounds contract

  • legal: 0 … N−1 — nothing else
  • first element a[0] · last element a[N−1]
  • C performs NO bounds check — the compiler trusts you completely
int a[5];
a[5] = 10;      /* ✗ OUT OF BOUNDS —
                   writes into somebody else's
                   memory: silent corruption,
                   wrong results, later crash */
⚠ OFF-BY-ONE — the #1 array bug. for (i = 1; i <= N; …) skips index 0 and steps off the end. The canonical loop is for (i = 0; i < N; …).
UNIT IV · arrays

for LOOPS FOR SEQUENTIAL ACCESS

Arrays and for were made for each other: one counter walks every element.

#define N 10
double t[N], sum, avg;
int i, above;

/* 1 · INPUT — fill the array */
for (i = 0; i < N; i = i + 1)
    scanf("%lf", &t[i]);

/* 2 · PROCESS — reduce to one value */
sum = 0.0;
for (i = 0; i < N; i = i + 1)
    sum = sum + t[i];
avg = sum / N;

/* 3 · PROCESS again — count a property */
above = 0;
for (i = 0; i < N; i = i + 1)
    if (t[i] > avg) above = above + 1;

/* 4 · OUTPUT — display */
for (i = 0; i < N; i = i + 1)
    printf("t[%d] = %.1f\n", i, t[i]);
THE TRINITY — almost every array program is these three passes: FILL → PROCESS → DISPLAY. Decide which pass you are writing before you write it.

double sq  = pow(temps[0], 2.0);     /* element → library function */

  • changing the parameter inside does not touch a[i]

UNIT IV · arrays

WHOLE ARRAYS AS ARGUMENTS

double average(const double a[], int n)   /* a[] is really a pointer */
{
    double s = 0.0;
    int i;
    for (i = 0; i < n; i = i + 1)
        s = s + a[i];
    return (s / n);
}

/* call: name alone — no &, no [] */
avg = average(temps, N);

Atomic facts

  • the array name decays into the address of element 0 — no copy is made
  • the function works on the original data: writes persist
  • arrays carry no size with them — always pass n too
  • const = a promise not to modify — the compiler enforces it
average(temps, N)
temps ──address of temps[0]──▶ a ──▶ [original cells]
N ───────────────────────────▶ n
⚠ NO BOUNDS CHECK INSIDE EITHER — if n is bigger than the real array, the loop walks into foreign memory. Pass the true size, every time.
UNIT IV · arrays

SEARCHING AN ARRAY — FIRST LOOK

/* linear search: index of key, or -1 */
int find(const int a[], int n, int key)
{
    int i;
    for (i = 0; i < n; i = i + 1)
        if (a[i] == key)
            return (i);      /* found here */
    return (-1);             /* not found  */
}
/* index of the maximum element */
int max_i = 0, i;
for (i = 1; i < n; i = i + 1)
    if (a[i] > a[max_i])
        max_i = i;
/* a[max_i] is the largest */
  • scan element by element until a match — works in any order
  • -1 is the conventional "not found" (a legal index is never negative)
  • min works the same with <; counting matches: replace return with a counter
FULL TREATMENT IN UNIT IX — binary search (needs sorted data, far faster) plus the three classic sorting algorithms that make it possible.

UNIT IV · arrays

MULTIDIMENSIONAL ARRAYS

int grid[3][4];             /* 3 rows × 4 cols */
grid[r][c]                  /* row, then column */

int m[2][3] = { {1, 2, 3},
                {4, 5, 6} };

/* nested loops walk the table */
int r, c;
for (r = 0; r < 3; r = r + 1) {
    for (c = 0; c < 4; c = c + 1)
        grid[r][c] = (r + 1) * (c + 1);
}
grid[r][c]      c=0  c=1  c=2  c=3
        r=0      1    2    3    4
        r=1      2    4    6    8
        r=2      3    6    9   12

memory: row-major — row 0 first,
then row 1, then row 2 (one flat block)
  • outer loop = rows, inner loop = columns; total cells = 3 × 4 = 12
  • summing everything: nest two loops around total += grid[r][c]
  • passing to a function: the column count must appear in the parameter — void show(int g[][4], int rows); (rows can be left out, cols cannot)
UNIT V · strings

STRING BASICS

C has no string type. A string is a char array ending in the terminator '\0' (value 0). Every rule of strings follows from that one fact.

char word[] = "hello";    /* h e l l o \0 : 6 bytes */
char city[20];

strcpy(city, "Pune");     /* copy, not =            */
printf("%s", city);       /* prints until '\0'      */
printf("%d", (int)strlen(word));  /* 5 — \0 not counted */

char ch = word[1];        /* 'e' — it IS an array   */
word in memory:
 index: [0] [1] [2] [3] [4] [5]
         h   e   l   l   o  \0   ← terminator

UNIT VI · recursion

THE NATURE OF RECURSION

A recursive function solves a problem by calling itself on a smaller version of the same problem — until the problem is trivial enough to answer directly.

int fact(int n)
{
    if (n <= 1)                /* BASE CASE   */
        return (1);            /* answer known */

    return (n * fact(n - 1));  /* RECURSIVE   */
}                              /* step: smaller n */

printf("%d", fact(4));         /* 24 */

The two laws

  1. Base case — at least one case answered without another call
  2. Progress — every recursive call moves strictly closer to the base case

Think of it as

fact(4) = 4 × fact(3)
fact(3) = 3 × fact(2)
fact(2) = 2 × fact(1)
fact(1) = 1  ← the ground floor

⚠ STACK OVERFLOW — miss the base case (or fail to shrink) and the function calls itself forever, eating memory until the program crashes. Every path must reach the base.
UNIT VI · recursion

TRACING A RECURSIVE FUNCTION

Every call gets its own stack frame — private copies of parameters and locals. Frames are LIFO: the last one called is the first to return.

fact(4)
 └─ 4 * fact(3)
      └─ 3 * fact(2)
           └─ 2 * fact(1)
                └─ returns 1        ◀ base reached
              returns 2 * 1 = 2
          returns 3 * 2 = 6
      returns 4 * 6 = 24            ◀ answers flow back UP
CALL STACK over time
push  fact(4)
push  fact(3)
push  fact(2)
push  fact(1) ── returns 1
pop   fact(2) ── returns 2
pop   fact(3) ── returns 6
pop   fact(4) ── returns 24  ✓
  • the four n's are four different variables — one per frame; n=4's copy waits while n=3 runs
  • nothing is multiplied until the base case returns — then results unwind in reverse
  • desk-check recursion exactly this way: draw the frames, push down, pop up
UNIT VI · recursion

RECURSIVE MATHEMATICAL FUNCTIONS

double power(double x, int n)        /* xⁿ */
{
    if (n == 0) return (1.0);        /* base        */
    return (x * power(x, n - 1));    /* xⁿ = x·xⁿ⁻¹ */
}

int gcd(int a, int b)                /* Euclid — elegant recursion */
{
    if (b == 0) return (a);
    return (gcd(b, a % b));          /* gcd(48,18) → 6 */
}

int fib(int n)                       /* 0 1 1 2 3 5 8 13 ... */
{
    if (n <= 1) return (n);
    return (fib(n - 1) + fib(n - 2));/* TWO calls — beware */
}
⚠ THE fib TRAP — fib(n-1) + fib(n-2) recomputes the same values again and again: exponential work. For real Fibonacci use a loop (O(n)). Recursion must earn its keep — when it mirrors the problem (gcd, tree walks) it shines; when it doesn't, iterate.
UNIT VI · recursion

RECURSION WITH ARRAYS & STRINGS

Arrays and strings shrink beautifully: drop the first element, recurse on the rest.

/* sum of an array, recursively */
int sum_arr(const int a[], int n)
{
    if (n == 0) return (0);            /* empty = 0 */
    return (a[0] + sum_arr(a + 1, n - 1));
}
/* a + 1 = "the array without its first element" */
/* print a string backwards */
void print_rev(const char s[], int n)
{
    if (n == 0) return;
    print_rev(s + 1, n - 1);   /* go deeper FIRST */
    putchar(s[0]);             /* print on the way back */
}
/* print_rev("cat",3) → "tac" */
  • base cases: n == 0 for arrays, '\0' / n == 0 for strings
  • work before the call prints forward; work after the call runs in reverse
  • recursive binary search is next unit's star — split the array in half, recurse into one half (Unit IX)

    out->y = (p.y + q.y) / 2.0;
}

UNIT VIII · text & binary file pointers

BINARY FILES

Text files store readable characters; binary files store the exact bytes of memory — faster, smaller, and structs go in and out unchanged.

/* WRITE one struct as raw bytes */
FILE *fp = fopen("emp.dat", "wb");
employee_t e = {101, "Asha", 250.0};
fwrite(&e, sizeof e, 1, fp);
fclose(fp);
/* READ records until none remain */
FILE *fp = fopen("emp.dat", "rb");
employee_t e;
while (fread(&e, sizeof e, 1, fp) == 1)
    printf("%d %s %.2f\n",
           e.id, e.name, e.rate);
fclose(fp);
  • fwrite(addr, item_size, count, fp) / fread(...) — fread returns items actually read: loop until it is 0
  • whole arrays at once: fwrite(arr, sizeof arr[0], N, fp);
  • random access: fseek(fp, k * sizeof e, SEEK_SET); jumps straight to record k — then one fread. No scanning needed.
WHEN BINARY — databases of structs, images, anything where text formatting would just slow you down and change the values.

int linear_search(const int a[], int n, int key)
{
    int i;
    for (i = 0; i < n; i = i + 1)
        if (a[i] == key)
            return (i);      /* found at i */
    return (-1);             /* not found  */
}

UNIT IX · searching & sorting

BINARY SEARCH

Requirement: the array must be SORTED. Compare the middle, throw away half, repeat.

int binary_search(const int a[], int n, int key)
{
    int lo = 0, hi = n - 1, mid;
    while (lo <= hi) {
        mid = (lo + hi) / 2;
        if (a[mid] == key) return (mid);
        if (a[mid] < key) lo = mid + 1; /* right half */
        else              hi = mid - 1; /* left  half */
    }
    return (-1);
}
key = 23 in [5 11 17 23 31 40]
lo=0 hi=5 → mid=2  a=17 < 23 → lo=3
lo=3 hi=5 → mid=4  a=31 > 23 → hi=3
lo=3 hi=3 → mid=3  a=23 == 23 ✓ return 3
3 probes instead of up to 6
nmax probes (log₂n + 1)
1,024≤ 11
1,000,000≤ 20
O(log n) — each probe halves the search space. This is why we bother sorting: one O(n log n) sort buys thousands of O(log n) searches.
UNIT IX · searching & sorting

BUBBLE SORT

Walk the array swapping out-of-order neighbours; the largest value bubbles to the end each pass. n−1 passes finish the job.

void bubble_sort(int a[], int n)
{
    int pass, i, tmp;
    for (pass = 0; pass < n - 1; pass = pass + 1)
        for (i = 0; i < n - 1 - pass; i = i + 1)
            if (a[i] > a[i + 1]) {
                tmp     = a[i];
                a[i]    = a[i + 1];
                a[i+1]  = tmp;
            }
}
[5 2 8 1]
pass 1: (5,2)swap (5,8)no (8,1)swap → [2 5 1 8]
pass 2: (2,5)no   (5,1)swap          → [2 1 5 8]
pass 3: (2,1)swap                    → [1 2 5 8] ✓
each pass locks one more element at the end
  • O(n²) — the nested loops make comparisons grow as n²
  • optimization: a swapped flag — if a whole pass swaps nothing, the array is already sorted; stop early
  • stable: equal values never cross each other
UNIT IX · searching & sorting

INSERTION SORT

Sort like playing cards: take the next element, slide bigger ones right, insert it into its place. The left part is always sorted.

void insertion_sort(int a[], int n)
{
    int i, j, key;
    for (i = 1; i < n; i = i + 1) {
        key = a[i];              /* card in hand */
        j = i - 1;
        while (j >= 0 && a[j] > key) {
            a[j + 1] = a[j];     /* shift right  */
            j = j - 1;
        }
        a[j + 1] = key;          /* drop it in   */
    }
}
[4 2 7 1]
i=1 key=2 → shift 4      → [2 4 7 1]
i=2 key=7 → nothing moves → [2 4 7 1]
i=3 key=1 → shift 7,4,2  → [1 2 4 7] ✓
  • O(n²) worst case (reverse order) — but O(n) on nearly-sorted data, the best of the simple sorts
  • stable, in-place, online (can sort as data arrives)
  • the practical choice for small n — even big libraries switch to it inside fancy sorts
UNIT IX · searching & sorting

SELECTION SORT

Repeatedly select the minimum of the unsorted part and swap it to the front — the sorted prefix grows by one each pass.

void selection_sort(int a[], int n)
{
    int i, j, min, tmp;
    for (i = 0; i < n - 1; i = i + 1) {
        min = i;                       /* assume   */
        for (j = i + 1; j < n; j = j + 1)
            if (a[j] < a[min])
                min = j;               /* hunt min */
        tmp    = a[i];                 /* swap to  */
        a[i]   = a[min];               /* the front*/
        a[min] = tmp;
    }
}
[29 10 14 37]
i=0 min=10 → swap → [10 29 14 37]
i=1 min=14 → swap → [10 14 29 37]
i=2 min=29 → self → [10 14 29 37] ✓
  • always O(n²) comparisons — even on sorted input
  • but at most n−1 swaps — the winner when writing data is expensive
  • simple to prove correct: after pass i, the first i+1 slots hold the i+1 smallest values, in order
