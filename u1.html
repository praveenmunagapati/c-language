00 · foundations

ALGORITHMS — THE RECIPE

An algorithm is a finite, ordered, unambiguous sequence of steps that transforms input into output and solves the problem. Every valid algorithm has five properties:

Input
Zero or more quantities supplied before it begins.
Output
At least one result produced — otherwise it solves nothing.
Definiteness
Every step is precisely stated — no ambiguity, ever.
Finiteness
It must terminate after a finite number of steps.
Effectiveness
Each step is basic enough to be carried out exactly.
algorithm — largest of three
ALGORITHM LargestOfThree
/* stepwise refinement: plain,
   numbered, language-free */

Step 1: read  a, b, c
Step 2: max ← a
Step 3: if b > max then max ← b
Step 4: if c > max then max ← c
Step 5: print max
Step 6: stop

/* written in pseudocode —
   structured English. Any C
   programmer can translate
   this directly.          */

00 · foundations

STRUCTURED PROGRAMMING

  • Top-down design — start with the whole problem, decompose into sub-problems, refine each until a step is directly codeable. Big problem → small modules.
  • Single entry, single exit — every block has exactly one way in and one way out. Control flow stays readable and traceable.
  • Three constructs suffice — Böhm & Jacopini proved any algorithm can be expressed with sequence, selection, repetition alone.
  • No goto — arbitrary jumps create "spaghetti" logic that no one can follow. Structured constructs replace them.
  • Divide & verify — test each module independently, then integrate. Correctness composes.
structured-vs-spaghetti.c
/* SPAGHETTI ✗ — where does flow go? */
  goto retry;
  ...
retry:
  scanf("%d", &x);

/* STRUCTURED ✓ — shape of logic
   is the shape of the code */
  do {
      scanf("%d", &x);
  } while (x < 0);

/* one way in →→ [ block ] →→ one way out */
WHY IT MATTERS
C is a structured language — if/else, while, for are the tools. Learning to design structured is learning to write C well.

01 · overview

C LANGUAGE ELEMENTS

hello.c — anatomy
/* Converts miles to kilometres */
#include <stdio.h>      ← preprocessor directive
#define KM_PER_MILE 1.609 ← named constant
int main(void)              ← entry point
{
  double miles, kms;        ← declarations
  printf("Enter miles> ");
  scanf("%lf", &miles);
  kms = miles * KM_PER_MILE; ← executable stmt
  printf("%f km\n", kms); ← \n = escape seq
  return (0);
}
  • Reserved words — int, double, if, while, return — fixed meaning, lowercase only.
  • Identifiers — names for variables & functions. Case-sensitive: Km ≠ km. Letters, digits, _; can't start with a digit.
  • Comments — /* ... */ between tokens, ignored by compiler.
  • Standard library — stdio.h gives printf / scanf prototypes.
  • Statements — end with a semicolon ;.

VARIABLES & DATA TYPES

Type Stores Typical range printf/scanf
int whole numbers −2,147,483,648 … 2,147,483,647 %d
char one character 'a', '7', '*' %c
float real (single) ≈ 7 significant digits %f / %f

A declaration tells the compiler the name and type of memory to reserve. A variable can hold only values of its declared type.

declare.c
/* declare before use — always */

/* invalid identifiers */

/* good style: meaningful names */
int letter_count; // ✓
03 · overview

EXECUTABLE STATEMENTS

Assignment
kms = miles * 1.609; — computes, then stores in the left-side variable. The old value is destroyed.
Input (scanf)
scanf("%lf", &miles); — copies data from keyboard into memory. The & (address-of) is required.
Output (printf)
printf("Value = %d\n", x); — placeholders in the format string are filled by the value list.
Function call
area = find_area(r); — transfer control, return a value, resume here.
Return
return (0); — exits main, 0 signals normal completion to the OS.
payroll.c
double hours, rate, pay;

printf("Hours worked> ");  // prompt
scanf("%lf", &hours);

printf("Rate per hour> ");
scanf("%lf", &rate);

pay = hours * rate;         // assignment

printf("Pay = $%f\n", pay);
⚠ ASSIGNMENT ≠ EQUALS
In C, = means "get, then store" — not mathematical equality. It's a copy operation, right to left.

ARITHMETIC EXPRESSIONS

Operator Meaning Example Result
+ − add / subtract 5 + 2.5 7.5
* multiply 3 * 4 12
/ divide 5 / 2 2 (int!)
/ divide (mixed) 5 / 2.0 2.5

⚠ INTEGER DIVISION TRAP
When both operands are int, / truncates the fraction. Cast or use a real operand: (double)5 / 2 → 2.5.
precedence.c
/* precedence, high → low */
( )                 1. parentheses
*  /  %             2. mult / div / mod
+  −                3. add / sub

/* left-to-right for equal precedence */
12 - 3 + 4  →  (12-3) + 4  →  13
10 / 5 * 2  →  (10/5) * 2  →  4

/* parentheses change everything */
(12 - 3 + 4) * 2   →  26
10 / (5 * 2)       →  1

/* mixed types: int promoted to double */
5 * 2.5   →  12.5
06 · overview

FORMATTING NUMBERS IN OUTPUT

format.c
double num = 123.456789;

printf("[%f]",   num);   → [123.456789]
printf("[%.2f]",  num);   → [123.46]
printf("[%9.2f]", num);   → [   123.46]
printf("[%-9.2f]",num);   → [123.46   ]
printf("[%d]",  42);      → [42]
printf("[%5d]", 42);      → [   42]
printf("[%c]", 'A');      → [A]
SPEC %n.mf
%9.2f → field width 9, precision 2 decimals, right-aligned by default; - flips it left. Money output: %.2f is standard.
%d
Print an int in decimal. Width %5d pads with spaces.
%f
Print a float/double; default shows 6 decimal places.
%c · %s
A single character, and a string of characters.
⚠ MISMATCH
A placeholder must match its value's type — %d with a double prints garbage. No compiler error, just wrong output.
01 · selection structures

CONTROL STRUCTURES & CONDITIONS

Relational Meaning Logical Meaning
< > less / greater && AND — both true
<= >= or equal || OR — either true
== equal to ! NOT — invert
!= not equal

A condition is an expression that evaluates to 1 (true) or 0 (false). C has no boolean keyword here — the number is the answer.

⚠ == vs =
x == 5 compares. x = 5 assigns and yields 5 (true!) — the classic bug.
condition.c
int x = 4, y = 9;

x < y              /* 1 — true  */
x >= y             /* 0 — false */
x == 4            /* 1         */

/* short-circuit evaluation */
(x > 0) && (y / x > 2)   // right side only if needed
(x < 0) || (y % x == 1)   // || stops at first true

/* operator precedence */
!  >  &&  >  ||
/* relational beat logical */
x > 0 && y > 0  ==  (x>0) && (y>0)

THE if STATEMENT

grade.c — compound statements
if (score >= 90)
    grade = 'A';              // single stmt

/* compound: braces make ONE block */
if (score < 60) {
    printf("Failing\n");
    grade    = 'F';
    failures = failures + 1;
}

/* two-way decision */
if (x != 0)
    result = y / x;
else {
    printf("Divide by zero!\n");

}

statement₁
then-block
false ↓
statement₂

  • Compound = braces { } treat a group as one statement. Dangling statements without braces belong to the if only.

03 · selection structures

DECISION STEPS IN ALGORITHMS

pseudocode — overtime pay
IF hours > 40.0
THEN
    pay = 40.0 * rate
          + (hours − 40.0) * rate * 1.5
ELSE
    pay = hours * rate
ENDIF

/* C translation — 1:1 mapping */
if (hours > 40.0)
    pay = 40.0 * rate
        + (hours − 40.0) * rate * 1.5;
else
    pay = hours * rate;
  • Pseudocode and flowcharts express decisions before code: if/then/else/endif mirrors C's if/else exactly.
  • Refinement: solve the simple case first, then add decisions around special cases (boundaries, invalid input).
  • Guard pattern — validate input before using it:
if (num_employees <= 0) {
    printf("Invalid data\n");
} else {
    avg = total / num_employees;
    printf("Average = %.2f\n", avg);
}

THE while STATEMENT

count.c — counting loop
/* prints 1 .. count      */
int count = 5;         — initialize
int i    = 1;

while (i <= count) {    — test BEFORE body
    printf("i = %d\n", i);
    i = i + 1;         — update: move forward
}
/* loop exits when i == 6 */
⚠ INFINITE LOOPS
Forget the update step and the condition never becomes false — the loop runs forever. Every loop needs init + test + update.

02 · repetition & loops

COMPUTING A SUM OR PRODUCT

accumulator.c
/* SUM: accumulate additions */
double sum = 0.0;         — start at identity
int    i;
for (i = 1; i <= 10; i = i + 1)
    sum = sum + i;         — running total
/* sum == 55 */

/* PRODUCT: accumulate factors */
double fact = 1.0;         — 1, not 0!
for (i = 1; i <= 5; i = i + 1)
    fact = fact * i;       — 5! = 120
PATTERN · ACCUMULATOR
Initialize the accumulator outside the loop, then update it inside with the running operation.
SUM → 0
Zero is the identity for addition — adding 0 changes nothing.
PRODUCT → 1
One is the identity for multiplication. Starting at 0 makes every product 0.

Trace it: sum = 0 → 1 → 3 → 6 → 10 → … → 55. Small traces prove loops correct.

03 · repetition & loops

THE for STATEMENT

for.c — the three-in-one header
for (i = 1; i <= n; i = i + 1)
     └─init──┘└─repeat-cond─┘└──update──┘
    printf("%d\n", i);

/* EXACTLY equivalent to: */
i = 1;
while (i <= n) {
    printf("%d\n", i);
    i = i + 1;
}

/* steps: init → test → body → update → test … */
/* update runs AFTER the body, every pass     */
  • Best for counting loops — when you know the number of repetitions in advance: init, condition, and update live together on one line, nothing is forgotten.
  • Loop-control variable i may be declared in the header: for (int i = 0; …).
  • Never modify the control variable inside the body — let the update expression do it.
  • Counting down works too: for (i = n; i >= 1; i = i − 1).
  • Off-by-one: <= n runs n times; < n runs n−1. Decide which you mean.
04 · repetition & loops

CONDITIONAL LOOPS

sentinel.c
/* loop until a sentinel value arrives */
printf("Enter scores (-1 to stop)> ");
scanf("%d", &score);

while (score != SENTINEL) {  −1
    sum   = sum + score;
    count = count + 1;
    scanf("%d", &score);   get next
}
avg = sum / count;
⚠ PRIMING READ
The first scanf happens before the loop; each pass reads the next value at the end. Both are required — miss one and the loop never advances.
SENTINEL-CONTROLLED
Repeat until a special "end of data" value arrives (e.g. -1, EOF). Count of repetitions unknown up front.
FLAG-CONTROLLED
while (!found) { … } — a 0/1 variable flips when the event occurs.
ENDFILE-CONTROLLED
scanf returns EOF when input ends: while (scanf("%d",&x) != EOF).
INPUT VALIDATION
Keep asking until the answer is legal: while (x < 0) { re-prompt; }

LOOP DESIGN

Answer three questions,
and any loop is correct.

1 · Initialize
How are the control variable and the accumulators set before the first test?
2 · Condition
What exactly makes the loop continue? When does it stop? What is true at exit?
3 · Update
What changes each pass so progress is guaranteed toward termination?
Body
What work is repeated — and what must stay outside (done once, not n times)?

06 · repetition & loops

NESTED LOOPS

times_table.c
/* inner loop restarts for EVERY
   outer pass — total iterations
   = outer × inner              */
int row, col;

for (row = 1; row <= 5; row = row + 1) {
    for (col = 1; col <= 5; col = col + 1) {
        printf("%4d", row * col);
    }
    printf("\n");   — end of row only
}
stdout
   1   2   3   4   5
   2   4   6   8  10
   3   6   9  12  15
   4   8  12  16  20
   5  10  15  20  25
  • Outer loop controls rows; inner loop fully completes for each single outer pass.
  • Use different control variables — row and col, never the same i for both.
  • Cost multiplies: 5 × 5 = 25 iterations; 100 × 100 = 10,000. Nested loops get expensive fast.
  • Statement placement matters — inside the inner loop repeats every pass; between the loops repeats once per row; outside runs once.

THE do-while STATEMENT

validate.c — test at the BOTTOM
do {
    printf("Enter rate (0-10)> ");
    scanf("%lf", &rate);
} while (rate < 0.0 || rate > 10.0);
/* body first — then the test */
syntax
do {
    statement(s);
} while (condition);   ← semicolon!
⚠ SEMICOLON REQUIRED
The ; after while (...) is mandatory — forgetting it is a syntax error.
body: statements
↓
condition ?
true ↺ repeat   ·   false → exit
  • Post-test loop — the body always runs at least once, even if the condition is false from the start.
  • vs. while — while is pre-test (may run zero times); do-while is post-test (runs ≥ once).
  • Classic use — input validation and menus: you must ask once before you can test the answer.
